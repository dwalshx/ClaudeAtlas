# Quick 260908-045: Reciprocal Pass v1 — declared-UA good agent Summary

A polite, declared-UA research crawler (`ClaudeAtlasBot/1.0 (+https://claudeatlas.com/bot)`) that made one read-only, meta-only pass over 27 operator domains from our request_log and produced the first "how the web treats a declared agent" dataset: **11.5% of responders block or challenge a polite declared agent; 7.7% negotiate markdown; 8/26 publish `/llms.txt`; 2 (ahrefs.com, meta.com) already publish Web Bot Auth key directories; claudeatlas.com passes its own probe.**

Per-target one-liners are in `docs/reciprocal-pass-report.md`. Eyeball of the classifications (nothing looked like a runner bug):

- **Blocked:** huawei.com and oracle.com — both `403 AkamaiGHost`, to the browser UA too (so not agent-specific). robots.txt itself 403s on both → policy `allow_all`, so the probes ran and got the 403 answer.
- **Challenged:** perplexity.ai — `403 cloudflare` with the challenge body (the browser UA is challenged as well).
- **robots_disallowed:** ovhcloud.com — `/robots.txt` is a 307 redirect loop; budget exhausted → conservative disallow-all; only 6 requests made, nothing else fetched. (Manual check worth doing: the loop may be a cookie/JS gate, in which case a human-facing robots.txt exists that we can't reach — that is itself a finding.)
- **Signers (2):** ahrefs.com and meta.com serve `/.well-known/http-message-signatures-directory` as `application/http-message-signatures-directory+json` (245 B / 250 B) — real Web Bot Auth key directories. cloudflare.com (spec author) does not on its apex.
- **Markdown negotiation (2):** cloudflare.com and claudeatlas.com — both `text/markdown; charset=utf-8`.
- **Cloaking (1):** amazon.com — agent UA gets 200 (≥512 KB), browser UA gets a `202` (2 KB) bot-check page. Status differs → flagged; it's the weak signal by design. meta.com renders "—" (insufficient) because its browser-UA request got a `400` (253 KB body) — classified `error`, so no comparison is made; worth a manual look, since the agent UA got a 200.
- **Catch-alls correctly rejected:** bytedance.com and alibabacloud.com return 200 `text/html` for every well-known path — all marked implausible (✗), so they don't inflate adoption counts.
- **robots posture:** amazon.com names 12 AI bots and disallows all 12; cloudflare.com and claudeatlas.com name 7 (none disallowed) and both carry a `Content-Signal`; 21 of 24 present robots files name no AI bot at all.

**Caveats on the dataset:**

1. The `/bot` URL in the UA was **not live** during this run (goes live when the orchestrator merges + deploys). Recommend one post-deploy re-run as the "official" v1 dataset so any operator who followed the link found the page.
2. Homepage `bytes` is right-censored at the 512 KB read cap when the server sends no `content-length` (6 targets show exactly 524,288 with `bytes_truncated: true`), so `size_bytes.max`/median understate bloat for the largest pages. The per-target `bytes_truncated` flag is in the JSON; raise `BODY_CAP_BYTES` in the probe module if the bloat signal matters.
3. The smoke + full run landed ~20 rows in our own `request_log` under UA `ClaudeAtlasBot` — harmless, and a useful check of how our classifier treats a declared agent.
4. Cross-host redirects honour only the target host's robots.txt (open question 6).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] cloakingDiff denominator contradicted the plan's own fixture**
- **Found during:** Task 1 (RED→GREEN)
- **Issue:** Plan formula `|agent-browser| / max(browser,1) > 0.30` gives 40/140 = 0.286 for the plan's "100k vs 140k → differs true" example, i.e. the spec was inconsistent with its test case.
- **Fix:** Symmetric relative difference, denominator = the smaller side (`|a-b| / max(min(a,b),1)`); both plan examples now hold and the verdict no longer depends on which UA got the bigger page. `size_ratio` is still agent/browser.
- **Files modified:** `scripts/lib/reciprocal-probe.js`
- **Commit:** `6cf6ef1`

**2. [Rule 1 - Bug] Standards matrix rendered 404s as "not fetched"**
- **Found during:** Task 2 control smoke eyeball
- **Issue:** `classifyResponse` maps a 404 to `error` (per the interface's "anything else → error"), and `renderReport`'s matrix rendered every `error` as "—" — so an absent `/llms-full.txt` looked like a network failure instead of a ✗.
- **Fix:** "—" is now reserved for `robots_disallowed` and status-less errors (true network failures); anything with a real status renders ✗. Added a test. The JSON is unchanged (status 404 was always recorded).
- **Files modified:** `scripts/lib/reciprocal-probe.js`, `scripts/lib/reciprocal-probe.test.js`
- **Commit:** `03f59fb`
