## Open items for Dan (pick-the-default already applied; nothing blocking)

1. **`robots_disallowed` conflates two things.** Of the 9, seven are explicit `User-agent: *` disallow-alls (instacart, reddit, reuters, yelp, facebook, trustpilot, marketwatch — `robots.policy: parsed`, `disallows_all_bots: true`). Two — **opentable.com** and **runningwarehouse.com** — are `robots.present: false, status: null, policy: disallow_all`, i.e. robots.txt was unreachable (timeout / network) and the runner's conservative RFC 9309 rule counted them as disallowed. The robots posture table shows the distinction via the `policy` column but the headline and By-tier counts do not. Suggested v1.2: a separate `robots_unreachable` result bucket (or re-probe those two).
2. **usnews.com is the one `error`** (homepage timeout at 15 s, 249 s total across retries and well-known paths). Nothing to fix; a single-target `--only usnews.com --out <scratch>` re-probe would tell us if it is persistent, but it would not merge into the committed dataset, so I did not run it.
3. **429s classified as `blocked`**: expedia.com (istio-envoy) and mcpmarket.com (Vercel; robots.txt itself 429'd) returned 429 to *both* the agent UA and the browser UA on first contact. Per spec 429 is a hard block, so the classification is correct, but these read as "rate-limited by default" rather than "bot-banned". Possible v1.2 distinction (`rate_limited`).
4. **rei.com** blocked on thin evidence: robots.txt 403 (treated allow-all), homepage 403 with a 357-byte body and no `Server` header, and the browser-UA comparison request errored. Classification is defensible; flagging in case it is a transient edge.
5. **Cloaking flag still noisy (18 hits).** The 4 size-based hits (microsoft.com, fastly.com, bible.com, jdpower.com) are the dynamic-size class already called out in v1. The 14 status-based hits are mostly "agent gets 403/503 challenge, browser gets 200" (amazon, openai, x.ai, wayfair, medium, zillow, akamai, humansecurity, whistleout, solereview, cnbc, irunfar) — those are real. **nih.gov and w3.org** are status-based hits on targets whose agent result is `allowed`, meaning the browser-UA request got a different status; worth an eyeball before the flag is published.
6. **request_log footprint**: this task's runs landed **20 rows** under `ClaudeAtlasBot` on claudeatlas.com (10 from the Task 2 smoke, 10 from the full pass), on top of the ~10 from this morning's v1 official run.
7. Not started (still deferred from v1, unchanged): public route/human page for the dataset, weekly cadence workflow, request signing, exclusion-list file, cross-host robots re-check on redirect, `--suggest-targets`, README / scope-doc updates for the tier scheme.
