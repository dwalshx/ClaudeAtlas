# Quick 260804-d5p: Versioned Catalog Composition Snapshot Summary

Adds a daily, committed `data/snapshots/<YYYY-MM-DD>.json` capturing the catalog's *composition* (record/indexed/duplicate totals, tier mix, per-entity-type breakdown, category distribution) — the compounding substrate for the future `/trends` page and downstream AEO trend consumers. Purely additive: one new script + test, one lint-allowlist entry, one daily-cron step. No scoring/filter/render code touched.

## What was built

- **`scripts/snapshot-catalog.js`** — pure `aggregateSnapshot(records, opts)` plus `loadCatalogRecords()` and `buildAndWriteSnapshot()`. Reads `data/{skills,plugins,mcp-servers}.ndjson` via the chunked `readNdjsonRecords` helper (missing inputs contribute zero), writes a bounded per-day JSON via an EPERM-tolerant tmp+rename. Import-safe via the filter.js invoked-as-script guard idiom; `__dirname` derived from `fileURLToPath(import.meta.url)`.
- **`scripts/snapshot-catalog.test.js`** — 7 `node:test` / `node:assert/strict` cases: import-safety (robust, non-false-failing), empty-catalog shape, indexed-vs-tiers decision, per-entity-type partitioning, legacy-shape robustness, category distribution, `_header` sentinel skip.
- **`scripts/check-banned-patterns.js`** — whole-file allowlist entry for `snapshot-catalog.js` (its one `JSON.stringify(snapshot, null, 2)` write is a bounded ~few-KB sidecar; catalog reads use the chunked helper, not a banned `readFileSync`).
- **`.github/workflows/daily-scrape.yml`** — new `Snapshot catalog composition` step after enrichment (fresh `is_duplicate`/`quality_tier`) and before the Astro build, gated `github.event_name != 'push'` like enrich; `data/snapshots/` added to the main-only "Commit skills data" git-add.

## Documented decision (for AEO trend consumers)

`totals.tiers` counts **ALL** records including duplicates (full-catalog denominator); `totals.indexed` **excludes** duplicates. So `featured + solid + listed === totals.records`, **not** `totals.indexed`. `categories` is counted over indexed records only. This is stated explicitly in the script header and enforced by a unit test so consumers aren't surprised the tier mix doesn't sum to `indexed`.

## Snapshot shape (design)

```json
{
  "schema_version": 1,
  "date": "YYYY-MM-DD",
  "generated_at": "<ISO>",
  "totals": { "records", "indexed", "duplicates", "tiers": { "featured", "solid", "listed" } },
  "by_entity_type": {
    "skill":      { "records", "indexed", "duplicates", "tiers": {...} },
    "plugin":     { ... },
    "mcp_server": { ... }
  },
  "categories": { "<slug>": <count among indexed> }
}
```

Canonical entity-type keys (`skill`/`plugin`/`mcp_server`) are always present (stable time-series keys even when a corpus is empty that day).

**4 new field groups added to the snapshot object:**

- `new_last_7d` (int) — records whose `scraped_at` parses to within 7 days of the snapshot date, over ALL analyzed records (missing/unparseable → not counted). Documented as a BEST-EFFORT GROWTH PROXY (scraped_at = last-scrape time, not first-seen).
- `maintenance: { active, abandoned }` — over INDEXED records only (consistent with `by_category`): active = `repo_pushed_at` within 90 days; abandoned = everything else (missing/unparseable pushed_at counts as abandoned, conservative).
- `unique_creators` (int) — distinct `repo_full_name` owner (prefix before `/`) over INDEXED records; missing repo_full_name skipped.
- `churn: { archived, duplicates }` — archived = `repo_archived === true` over ALL analyzed; duplicates = `is_duplicate === true` (mirrors `totals.duplicates`).

**Determinism:** `aggregateSnapshot` gained an optional `nowMs` opt (defaults to `Date.parse(timestamp)`) so the 7d/90d windows never depend on real `Date.now()` in tests.

**Test coverage:** 2 new `node:test` cases (fixture exercising every new field with a fixed reference date; `nowMs`-override case) plus updated assertions in the empty-catalog case. Total **9 pass, 0 fail**. `npm run check:patterns` → clean. Local dry run over the live 26,707-record catalog (skills + plugins + mcp) emitted a well-formed object with all new fields populated (active=2111 / abandoned=24596, unique_creators=5167, churn.archived=3; new_last_7d=0 is correct for the April-vintage `scraped_at` values in the committed catalog).
