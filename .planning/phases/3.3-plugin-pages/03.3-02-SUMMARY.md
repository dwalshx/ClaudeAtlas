## Decisions Made

- **Prefix-tolerant skill-ID resolution:** the plan's interfaces block stated `bundled_skills` carry `skill:`-prefixed entity IDs, but on-disk ground truth (verified against `data/skills.ndjson`, 23,047 records) shows skill IDs are legacy-UNPREFIXED and `bundled_skills` entries match them directly. `resolveBundledSkills` does a direct lookup first, then retries with the `skill:` prefix stripped — both forms resolve, future-proofing against a typedef-conformant pipeline change.
- **Legacy listing normalization:** on-disk `marketplace_listings` are still bare path strings (sample predates Plan 01's pipeline change); `normalizeListing` accepts both shapes so the loader works against today's data AND post-Plan-01 regenerated data.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan's assumed `skill:` ID prefix doesn't exist on disk**
- **Found during:** Task 1 (RED test design, data inspection)
- **Issue:** Plan interfaces block claimed `bundled_skills[]` entries are `skill:<repo>/<path>/SKILL.md`; real data has unprefixed skill IDs (0 of 23,047 skills carry the prefix). A resolver keyed only on prefixed IDs would resolve nothing.
- **Fix:** `resolveBundledSkills` resolves the on-disk unprefixed form directly and normalizes a `skill:` prefix away on miss; test covers both forms.
