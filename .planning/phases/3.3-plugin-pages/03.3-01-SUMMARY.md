## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] upcastPluginRecord's arr() would silently drop the {path,name} listing objects**
- **Found during:** Task 2 (pre-implementation read of legacy-skill-reader.js)
- **Issue:** `upcastPluginRecord` passes `marketplace_listings` through `arr()`, which filters elements to `typeof x === 'string'`. The plan's new object entries would be dropped during the v2 upcast — voiding the declared-name feature entirely AND making listing-only plugins (no plugin.json) fail the HAS_MANIFEST_OR_LISTING slop gate (asymmetric, silent data loss).
- **Fix:** Added `listingArr()` accepting both `{ path }` objects (3.3+) and bare strings (pre-3.3 legacy); `marketplace_listings` now routes through it. Two end-to-end tests pin the behavior.
- **Files modified:** scripts/lib/legacy-skill-reader.js
- **Verification:** `marketplace-resolve.test.js` END-TO-END tests pass; `legacy-skill-reader.test.js` (6 tests) still green
- **Committed in:** 431165f (Task 2 commit)

**2. [Rule 3 - Blocking] Module-level GITHUB_TOKEN process.exit(1) killed test imports**
- **Found during:** Task 1 (test design)
- **Issue:** `scrape-plugins.js` exited at import time without `GITHUB_TOKEN`, making the exported checkpoint functions untestable; with a token set, the unguarded `main()` call would have started a real scrape from the test import.
- **Fix:** Token check moved into `main()`; `main()` invocation wrapped in the invoked-as-script guard (same idiom as filter-plugins.js, which the plan's action explicitly called for). Script-mode behavior verified unchanged.
- **Files modified:** scripts/scrape-plugins.js
- **Verification:** `env -u GITHUB_TOKEN node --test ...` passes (no network, no exit); `env -u GITHUB_TOKEN node scripts/scrape-plugins.js` still errors with exit 1
- **Committed in:** f8837fb (Task 1 commit)

**3. [Rule 3 - Blocking] check-banned-patterns line-anchored allowlist broke on line drift (×2)**
- **Found during:** Task 1 and Task 2 verification
- **Issue:** The allowlist pins bounded sidecar writes to exact line numbers (scrape-plugins.js:452, filter-plugins.js:273). Both files grew above those lines, so `check:patterns` flagged the pre-existing allowlisted writes as new violations.
- **Fix:** Updated both anchors (452→483, 273→290) with drift causes documented in the reason strings — the established convention ("Line shifted by ...") used by prior phases.
- **Files modified:** scripts/check-banned-patterns.js
- **Verification:** `npm run check:patterns` → "lint mode: clean (0 baselined, 0 new)"
- **Committed in:** f8837fb + 431165f

**4. [Rule 2 - Missing Critical] CLAUDE.md PluginExtra block synced to the new shape**
- **Found during:** Task 2
- **Issue:** CLAUDE.md's data-model section (loaded into every future session) still documented `marketplace_listings: string[]` — stale canonical docs would actively mislead Plans 02/03, which consume the new shape.
- **Fix:** One-block update mirroring the types.d.ts comment (path/name semantics + legacy-string note).
- **Files modified:** CLAUDE.md
- **Verification:** grep confirms the `{ path: string; name: string | null }` form
- **Committed in:** 431165f
