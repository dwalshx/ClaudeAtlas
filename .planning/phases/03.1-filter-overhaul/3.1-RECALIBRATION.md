## Deviations / surprises

1. **Featured tier exploded from 501 → 13,055** (a 26× growth, way over the plan's "≤2×" soft gate).

   Root cause: dropping MAX_PER_REPO surfaces 29k+ previously-suppressed records. Those records were never re-scored under the old filter (it returned early for over-capped repos), so once admitted, their scoring shape (heavy reliance on stars + recency) puts most of them into the Featured tier under the existing thresholds.

   This is the **R1 recalibration explosion** documented in 3.1-CONTEXT.md. Three follow-ups can address it:
   - Dedup catching more pairs once vectors are computed for the full 23k corpus (CI will do this).
   - Tier threshold recalibration in a follow-up phase (3.1.1 or 3.6 "Top rename") — the plan's locked Decision H said tier thresholds stay absolute, but at this catalog size that's clearly producing too-permissive "Featured" labels.
   - Re-introducing a soft minimum signal floor (e.g., MIN_STARS=2 or quality_score >= 50) if dedup doesn't sufficiently rebalance.

   **Recommendation:** proceed to Task 10 CI run to see the post-full-embed numbers. If Featured stays > 5k after enrich on a complete vector set, plan a tier recalibration in Phase 3.1.1 BEFORE shipping the homepage redesign in Phase 3.4.

2. **Vector coverage is 1,078/23,056 (4.7%) locally.**

   This is the **FLAG 4 caveat** the plan called out: `OPENAI_API_KEY` is not set locally, so `npm run embed` could not regenerate vectors for the 21,978 newly-admitted records. The 38 duplicates found are a strict undercount of what the CI run will surface. Expected duplicate count post-full-embed: ~30-50% of catalog (per RESEARCH.md §R1 hypothesis on mega-repo internal duplication). With dedup hiding those from default browse helpers (Task 7.5), the visible catalog should land closer to 8-15k.

   **The numbers in this report are smoke-level, not ground truth.** They prove enrich.js wires up, finds the empirically-known dup pairs, and produces plausible novelty quantiles. The real recalibration numbers come from the Task 10 CI run.

3. **Slug collisions are 402, not 13.**

   The plan estimate was correct for the pre-3.1 catalog but stale relative to the dropped-gates output. The assignSlugs() helper scales to N collisions by design (no hardcoded constant), so this is a documentation issue not a functional one. The recalibration audit captures the real number; CLAUDE.md and the plan can be updated in a follow-up to reflect "the number of collisions is data-driven and grows with the catalog."

4. **Catalog grew to 23,056 records**, in the upper range of the plan's [5k, 15k] expectation. With dedup applied to the full vector set (CI), real visible count should land lower — likely 12-18k.
