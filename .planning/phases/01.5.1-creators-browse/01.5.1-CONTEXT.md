# Phase 1.5.1: Creators Browse Page - Context

**Gathered:** 2026-04-11
**Status:** Ready for planning
**Mode:** Autonomous (post-ship tweak mini-phase)
**Parent:** Phase 1.5 (shipped)

<domain>
## Phase Boundary

Build a full-catalog creator browse page at `/creators/all/` that lets visitors find, sort, and filter every creator in ClaudeAtlas (all 776 today). Complements the existing `/creators/` leaderboard which surfaces only the top-10 per category.

User question this answers: "Show me every creator and let me find the one I care about."

Explicitly in scope:
- Sortable columns (username, skills count, Featured count, total stars, Total Quality, first commit date)
- Free-text filter on username
- Category filter (show only creators with a skill in category X)
- Creator type filter (Organization vs User vs both)
- URL query params so a filtered/sorted view is shareable
- Link from /creators leaderboard to this page

Explicitly NOT in scope:
- Pagination — 776 rows fits comfortably in a single client-side table with no virtualization. Revisit at 5k+ creators.
- Server-side filtering — everything is pure client JS on a build-time-embedded dataset. Matches existing static-site discipline.
- Writable state (favoriting, etc.) — read-only browse.
- Cross-phase surfaces like a "recently viewed creators" — Phase 2+ item.
</domain>

<decisions>
## Implementation Decisions

### Route
- `/creators/all/` (trailing slash per Astro default)
- Sibling to existing `/creators/` leaderboard and `/creators/[username]/` profiles
- New file: `src/pages/creators/all.astro`

### Data loading
- At build time, `getCreators()` already produces everything we need: `username, avatar_url, type, total_skills, tier_counts, total_stars, avg_quality_score_precise, total_quality_score, categories, first_commit_at`.
- Serialize the full creator array into a `<script type="application/json">` block in the page, then hydrate into a JS variable client-side.
- ~776 × ~400 bytes/entry ≈ 310 KB before gzip, fine for a single page load. Avatars already lazy-load.

### Table structure
- Columns (all sortable, click header to sort, click again to reverse):
  1. Avatar (not sortable, just display)
  2. Username
  3. Type (User / Org icon)
  4. Skills (total_skills)
  5. Featured (tier_counts.featured)
  6. Stars (total_stars, deduped per-repo from Phase 1.5 tweak batch)
  7. Total Quality (total_quality_score)
  8. First commit (first_commit_at — earliest skill creation date)
- Default sort: Total Quality descending (matches the leaderboard's headline metric)
- Sort indicator: up/down arrow next to the active column header, both arrows dim when inactive

### Filters (top of page, above the table)
- **Search box** — filters by username substring match, case-insensitive. Debounced 150ms.
- **Category chips** — 8 category chips (from the existing 8 categories in pipeline-stats.json), click to toggle. Multi-select = creator must have a skill in AT LEAST ONE of the selected categories (OR, not AND — less restrictive, more useful).
- **Type toggle** — 3-state segmented control: "All / Users / Orgs". Default: All.
- **Result count** — "Showing N of 776 creators" above the table. Updates live as filters change.
- **Clear filters button** — appears when any filter is non-default, resets everything.

### URL query params
Sync visible state to URL via `history.replaceState` (no new history entries, doesn't spam back button). Params:
- `q` — search query
- `sort` — column key (skills | featured | stars | quality | first_commit | username)
- `dir` — asc | desc
- `cat` — comma-separated category slugs
- `type` — user | org (omitted for all)

Read params on page load to restore state. Write params on every state change.

Example shareable URL:
`/creators/all/?sort=quality&dir=desc&cat=code-and-development&type=org`

### Performance
- All 776 rows rendered into DOM at build time (no virtualization)
- Sort + filter runs on a cached array, updates DOM visibility via inline `style.display`
- Each filter action is O(n) which is trivial at this scale (<1 ms per filter change)
- Avatars use `loading="lazy"` so only visible ones fetch on load

### Accessibility
- Sortable headers use `<button>` (not `<th>` with click handler) for keyboard activation
- Sort state announced via `aria-sort="ascending|descending|none"` on the `<th>` element
- Filter controls have proper `<label>` associations
- Skip-to-results link for keyboard users jumping past the filter bar

### Design language
- Reuses existing color palette (gray-950 bg, atlas-400 accents, amber-500 Featured, emerald-500 Solid)
- Table style inspired by existing Methodology page's quality-signal table
- Filter chips reuse the existing `CategoryChip.astro` component where possible
- Dark theme only, matches the rest of the site
</decisions>

<deferred>
## Deferred Ideas

- **Virtualized table** (for >5k creators) — not needed until catalog grows
- **Saved views / bookmarks** — URL params give you shareable state which is enough
- **Export to CSV** — backlog, low-effort add later if anyone asks
- **Column customization** (show/hide columns) — defer until users ask
- **Second sort order** (e.g. "sort by stars within quality ties") — current tiebreakers are fine
- **Search by category name or tier** — free text search is username-only for v1
- **Search history or suggestions** — Phase 2+
</deferred>
