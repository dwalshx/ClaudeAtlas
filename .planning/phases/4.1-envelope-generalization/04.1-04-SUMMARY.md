- **`scripts/lib/access.js`** implements the D-03 contract verbatim: `emptyAccess()` (fresh spec-shaped literal, enums `'unknown'`, numbers `null`, arrays `[]`, provenance `{}`), `mergeAccess(base, partial)` (structuredClone deep-fill, only keys present on the base group are copied, unknown top-level keys ignored, provenance normalised, base untouched), `setAccessField(access, path, value, prov)` (`group.key` | `formats` | `transport`; throws `unknown path` for `provenance`, unknown groups/keys and 3-segment paths; stamps `{ method 'manual', source_url null, confidence clamp01(1), checked_at now }` defaults), `accessClarity(access)` (one third per known auth / cost model / rate limit, each × provenance confidence; notes-only rate limit earns half credit — documented in the JSDoc as the data.gouv.fr free-text case), plus `normalizeProvenance` and `UNKNOWN`.
- **`scripts/lib/url-host.js`** — `hostOf(url)`: `'api.stripe.com'` for the Stripe base URL, `'noaa-ghcn-pds'` for `s3://noaa-ghcn-pds`, `''` for `''`/`null`/`'not a url'`; never throws.
- **`buildCommonFields(rec, opts = {})`** now has two visibly side-by-side `repoFields` modes: nullable (`str`/`num`/`bool`/`Array|null` for the 13 coerced fields) and github-origin (byte-identical to the pre-4.1 expressions). `repo_license`/`repo_language`/`repo_description` stay `?? null` in both. `body_length` falls back to `description.length` in nullable mode; `source` defaults to `opts.defaultSource`. `originFields(rec, { fallbackKind })` is spread right after `description`.
- **`upcastSkillRecord`** (which inlines its own field list) gains only `...originFields(rec)` after `description` — the rest of the skill list is untouched for property-test parity.
- **`backfillOriginInPlace(rec)`** on the v2 passthrough: sets `origin`/`home_url`/`docs_url` only where `undefined`, api/dataset fall back to a manual origin, same object returned. The existing `'Task 6: v2 record passes through unchanged'` identity assertion still passes.

## Decisions Made

- **The D+7 delete plan for `legacy-skill-reader.js` is superseded.** The file header still said "deleted at the D+7 cutover commit", but `filter.js`, `filter-plugins.js` and `filter-mcps.js` route every record through `upcastRecord` on every cron run, and this plan makes it the single choke point for `repo_*` nullability and origin defaults. The header now says rename at cutover, do not delete.
- **Nullability is decided per record, not per type.** `nullableRepo = !rec.repo_full_name` — an api with a resolved GitHub repo (fixture 4, `github/rest-api-description`) gets the exact skill coercions, keeping the "unbranched downstream" property D-02 is after.
- **Manual-origin fallback for feeds.** When an api/dataset input has no `origin`, `originFields` produces `kind: 'manual'`, `source: 'manual'`, `source_id: id || name`, `source_url: home_url` — never a fabricated github origin. `backfillOriginInPlace` applies the same rule to already-v2 api/dataset records.
- **`schema_version` stays 2**, pinned by a comment above the constant: a bump would make `assertKnownSchemaVersion` reject every production file until regenerated.
- **Grep hygiene for acceptance criteria.** The plan's `mergeAccess(emptyAccess(), rec.access)` → 2 grep counted a literal in my Task 2 header JSDoc as a third hit; the comment was reworded so the grep measures call sites only (included in the Task 3 commit).
