## Decisions Made

- **The dedup scope chain is `repo_full_name ?? origin.source_id ?? id ?? ''`.** `repo_full_name` first keeps skills byte-identical; `origin.source_id` is the source-native key that distinguishes two providers' `weather` apis; `id` is the final fallback so the `same`/`distinct` halves of common.rules test 3 both hold.
- **`HAS_DOWNLOAD_OR_LANDING` stays** even though `HAS_HOME_URL` already supplies the landing half — kept for parity with D-06 wording and commented as only mattering if `HAS_HOME_URL` is relaxed. A landing page alone passes (many portal datasets expose files only behind it).
- **Recipe `computeId` is the parity twin of the upcaster default**, not an independent scheme: same `hostOf`, same `provider` fallback, same `origin.source/source_id`. The 8-fixture replay is the drift guard; 4.2/4.5 harvesters should extend `apis-mini`/`datasets-mini` rather than invent new id rules.
- **Pathspec commits for parallel executors.** After `8d893f5` swept in another plan's staged files, the remaining commits in this plan use `git commit --only -- <paths>` semantics (add + commit in a single chained command for new files) so the shared index cannot leak.
