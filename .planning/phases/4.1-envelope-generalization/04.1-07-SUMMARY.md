## Decisions Made

- **`slugParts` does not slugify.** `name` / `provider` / `publisher` pass through verbatim, exactly as skill names always have; slugifying here would silently rewrite every skill slug and invalidate `data/slug-redirects.json`. Harvesters (4.2 / 4.5) must supply slug-safe values — documented in the resolver's JSDoc.
- **Tie-break fallback is `repo_full_name ?? id ?? ''`.** `??` (not `||`) keeps skills byte-identical (non-empty string) while letting null-repo feeds fall through to the shorter id; the Plan 01 fixture ids are stable, so the winner is deterministic across runs.
- **`install_command: null` for null-repo registry entries** rather than a fabricated string; the registry stays skills-only (`loadSkillsArray`) until 4.3, so this branch is currently exercised only by the round-trip test.
- **Proved CLI parity empirically.** The worktree happens to carry the legacy `data/skills.json`, so the HEAD-vs-new comparison on 1,105 real entries replaces an inspection-only "byte-identical" claim.
- **Import placement in `slug.js`.** The `hostOf` import and `slugParts` sit above the `assignSlugs` JSDoc (which carries that function's `@param` / `@returns`) rather than between the doc block and the function, so the doc stays attached to `assignSlugs`.
