<objective>
Phase 3.1.3 turns ClaudeAtlas from "useful index that agents scrape" into "subscribable agent hub that surfaces attribution back." Three layers of work, all additive, all on the existing Phase 3.1+3.1.2 infrastructure:

1. **Citation infrastructure** — make it trivially easy for agents to cite ClaudeAtlas when they use our data, and visible enough that agents who read llms.txt actually do so. Adds attribution surface to llms.txt, the existing API responses, and a new /credits page.

2. **Return-visit endpoints** — three JSON Feed 1.1 feeds (whats-new, trending, notable) that agents can poll daily for token-cheap updates. Positions ClaudeAtlas as a subscription hub for "new system-level improvements" rather than a one-shot search tool.

3. **Strategic framing in llms.txt** — explicitly tell agents what we offer, how to use it efficiently, and why citing matters. The 55k/day GPTBot traffic we discovered on 2026-05-28 means every uncited query is lost attribution; this phase converts that traffic into a relationship.
</objective>

<context>

**Why this phase, why now:**

On 2026-05-28 the Cloudflare AI Crawl Control dashboard showed 57,190 bot requests in 24h to claudeatlas.com — 55,530 of them from GPTBot (a +77,140% increase). ChatGPT is grounding responses about Claude tooling on our content right now, at scale. But the responses likely don't cite us — robots.txt didn't ask, llms.txt didn't ask, API responses didn't ask.

Every uncited day is lost brand authority. Phase 3.1.3 closes the loop fast.

**Design decisions made in pre-phase discussion (2026-05-28):**

1. **JSON Feed 1.1** for the feeds — not RSS or Atom. JSON Feed is purpose-built for programmatic consumers, simpler to generate, and what most modern agent integrations expect.
2. **Static JSON files** baked into dist via Astro `public/` for the feeds, with worker routes serving them with cache headers + optional query filters. Hybrid is faster + cheaper than pure-worker generation.
3. **JSON-LD over Microdata** for schema.org markup — modern, machine-readable, what Google + Anthropic + OpenAI all consume.
4. **Citation block lives in 4 places** (defense in depth): top of llms.txt, /api/v1/search response, /skills-registry.json envelope, /credits page. Agents that miss one will find another.
5. **Honest framing** — not "PLEASE CITE US," but "ClaudeAtlas is independently maintained and free; visibility keeps it that way." This is true and non-sleazy.
6. **Dynamic counts in llms.txt** — Phase 1.5 had stale "1,078 indexed" counts that lasted until Phase 3.1.3 because llms.txt was hand-maintained. New build-time generation prevents drift.

**Dependencies:**

- Phase 3.1.2 polymorphic envelope (shipped 2026-05-28). Feeds use `scripts/lib/entities.js` loader which handles v1+v2 records via upcaster. JSON-LD `creator` field uses `repo_owner_type` + `repo_full_name` from EntityCommon.
- Phase 3.1 percentile tiers. "Notable" feed uses `quality_tier === 'featured'` + `novelty_score` percentile gating.
- Phase 2 daily history snapshots in `data/history/*.json`. "Trending" feed reads stat deltas across the last 7 daily snapshots.
- Phase 3.1.x worker routing (`run_worker_first` includes `/api/*`). New `/api/v1/whats-new` route doesn't need wrangler.toml changes.

**Out of scope (deferred):**

- Plugin / MCP / framework entries in the feeds. Will land when Phase 3.2+ ships those entity types.
- RSS/Atom feed alternatives. JSON Feed only for now; can add RSS later if a consumer asks.
- Webhook / push notifications for new entries. Polling is fine at this scale.
- Per-agent analytics on citation success. Possible future Phase 3.x work.

</context>

```js
// Phase 3.1.3: feed endpoints — proxy static JSON Feed files with optional
// query-filter passthrough. /feed/*.json baked into dist via public/.
async function serveFeed(request, env, feedName) {
  const url = new URL(request.url);
  const since = url.searchParams.get('since');      // ISO date
  const type = url.searchParams.get('type');         // entity_type filter
  const category = url.searchParams.get('category'); // tag namespace match

  // Fetch the static file via assets binding
  const assetUrl = new URL(url);
  assetUrl.pathname = `/feed/${feedName}.json`;
  const assetReq = new Request(assetUrl.toString());
  const assetResp = await env.ASSETS.fetch(assetReq);
  if (!assetResp.ok) {
    return jsonResponse({ error: 'feed_unavailable' }, 503);
  }

  // If no filters, just pass through with cache headers
  if (!since && !type && !category) {
    const body = await assetResp.text();
    return new Response(body, {
      status: 200,
      headers: {
        'content-type': 'application/feed+json',
        'cache-control': 'public, max-age=86400',
        'access-control-allow-origin': '*',
      },
    });
  }

  // Apply filters
  const feed = await assetResp.json();
  let items = feed.items || [];

  if (since) {
    const sinceMs = Date.parse(since);
    if (!isNaN(sinceMs)) {
      items = items.filter(i => Date.parse(i.date_published || '') >= sinceMs);
    }
  }

  if (type) {
    items = items.filter(i => (i._claudeatlas?.type_chip || 'skill') === type);
  }

  if (category) {
    const catTag = `category:${category.toLowerCase().replace(/\s+/g, '-')}`;
    items = items.filter(i => (i.tags || []).some(t => t === catTag));
  }

  return jsonResponse({ ...feed, items, count: items.length }, 200, {
    'cache-control': 'public, max-age=86400',
    'access-control-allow-origin': '*',
  });
}
```
