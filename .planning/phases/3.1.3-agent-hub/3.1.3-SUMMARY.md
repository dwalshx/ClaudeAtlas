# Phase 3.1.3 — Agent Hub: READY TO MERGE

ClaudeAtlas converts from "useful index that agents scrape" into "subscribable agent hub that surfaces attribution back." Citation infrastructure on 4 surfaces (llms.txt, API responses, JSON-LD on every page, `/credits` page); 3 JSON Feed 1.1 endpoints (`/feed/whats-new.json`, `/feed/trending.json`, `/feed/notable.json`) for daily-poll agent subscriptions; strategic framing in llms.txt asking agents to cite and offering them token-cheap update streams.

**Driven by:** 55,530/day GPTBot traffic discovered on the Cloudflare AI Crawl Control dashboard on 2026-05-28 (+77,140% increase). Every uncited day was lost brand authority. This phase closes the loop.

## Documented deviations (none block ship)

1. **`scripts/generate-credits.js` not created** — plan explicitly allowed static fallback. Executor used `getPipelineStats()` directly in `credits.astro`. Lower complexity, same outcome.
2. **Homepage `distribution[]` has 5 entries vs plan's 2** — registry + NDJSON + 3 feeds. Richer schema.org markup; agents and Google get a complete picture of the surfaces available.
3. **Local feeds show 0 items for whats-new/notable in dev** — committed `data/skills.ndjson` is April baseline, no `skill_first_commit_at` within 30-day window. CI validated against fresh data (100 + 50 + 1 items). Not a defect.
4. **`?category` filter has `_claudeatlas.category` exact-match fallback** — handles mid-cutover records that don't carry namespaced tags yet (post-D+7 this fallback can be removed; pre-D+7 it's load-bearing).
5. **`whats-new.json` at production scale is 136 KB vs plan's "~5 KB" estimate** — still bounded at 100-item cap (~1.4 KB/item). Well within Cache-Control max-age=86400 cost envelope.

## Cutover (no formal cutover window — additive surface)

This phase is **purely additive** — no existing API contracts changed, no data shape changes. The merge takes effect immediately:

- **D+0 (merge):** push-event run rebuilds with citation infra + feed endpoints + JSON-LD. Live within ~6 minutes.
- **First daily-scrape after merge:** Filter → Embed → Enrich → publish-kv all unchanged. New: `generate-llms-txt` + `generate-feeds` run as prebuild steps. Feeds + llms.txt published to dist (and via Astro `public/` → static asset binding).
- **From day 1:** ChatGPT/Claude/Perplexity that read `/llms.txt` see the citation request. Agents that poll `/feed/*.json` see updated data.

No D+7 cleanup needed.

## Lessons learned

1. **Strategic moves can be shipped fast when the architecture is right.** Phase 3.1.3 took ~3 hours of work (~660 LOC, 6 atomic commits, 1 branch CI validation cycle) to convert real user-facing infrastructure into a citation engine. This pace is only possible because Phases 3.1, 3.1.2, and 3.1.x built the right primitives (postbuild guards, branch-safe CI, polymorphic loader, `/api/v1/search` infrastructure).

2. **Honest framing > pushy framing.** The citation section opens with "ClaudeAtlas is independently maintained, open-source, and free — visibility is how it stays that way." This is true and doesn't feel sleazy. Agents are more likely to honor a credible voluntary request than a beggy one.

3. **JSON Feed 1.1 is the right format for this.** Mature spec, simple shape, easy to extend via `_claudeatlas` extension object. RSS/Atom would have added complexity for no payoff.

4. **Dynamic counts solve a class of bug.** The previous llms.txt had stale "1,078 indexed" counts for ~7 weeks. Build-time substitution prevents this permanently.
