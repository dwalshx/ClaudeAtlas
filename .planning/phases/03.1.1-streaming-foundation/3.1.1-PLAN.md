## Why this plan exists, in one paragraph

Three CI crashes today and three more latent V8-string-limit failures on
main are the *symptom*. The *disease* is that the entire pipeline materializes
multi-hundred-megabyte JSON arrays as single strings at every read/write
boundary. F1 fixes the disease: it migrates the two load-bearing data files
to NDJSON, cherry-picks the proven streaming helpers from the
`phase-3.1-archive` commits, replaces the daily git-commit-back of
`skills.json` with a release-asset publish (so the repo doesn't bloat by
~70 GB/yr at projected catalog scale), introduces tier-aware rendering via a
**KV-backed per-slug lookup** in the worker (Rev 2 decision A) to get past
the 20k Cloudflare static-asset cap WITHOUT reintroducing the bug class in
the worker, installs CI gates that prevent the same patterns reappearing,
and preserves SEO via explicit sitemap customPages config (Rev 2 B1/B2).
Zero user-visible behavior change.

## Tier-aware rendering: request flow (Rev 2 — resolves R2 / B5)

**Build time (`npm run build` inside daily-scrape.yml):**
1. `gh release download skills-latest --pattern skills.ndjson --output data/skills.ndjson`
2. `npm run check:tier-budget` — fails build if Top+Solid > 18k.
3. `npm run build` runs Astro static build.
4. `src/pages/skills/[...slug].astro`'s `getStaticPaths()` returns ONLY Featured/Top/Solid skills.
5. Astro emits `dist/skills/<slug>/index.html` for those records (~5-10k pages at projected size).
6. `@astrojs/sitemap` is configured with **`customPages` enumerating EVERY slug from skills.ndjson regardless of tier** (Rev 2 B1/B2) so Listed slugs appear in sitemap-0.xml even without a dist/ entry.
7. `wrangler deploy` ships `dist/` to Cloudflare Workers Static Assets binding.

**Publish time (after filter, before build, inside daily-scrape.yml):**
8. `npm run publish:kv` reads `data/skills.ndjson` line-by-line via streaming
   and upserts each record to KV binding `SKILLS_KV`, keyed by url-safe slug.
   Uses Cloudflare's bulk KV write API (`PUT /accounts/{id}/storage/kv/namespaces/{ns}/bulk`, up to 10k keys per request). Incremental:
   only upserts records whose `content_sha` differs from `data/kv-published.json` baseline.

**Runtime — request for Top/Solid slug (`/skills/anthropic/code-review/`):**
- Static asset path matches → returned directly. **Worker is not invoked.** ~10 ms.

**Runtime — request for Listed slug (`/skills/random-user/niche-tool/`):**
- Static asset path 404s.
- `worker/index.js` checks `/skills/*/` before final fallthrough:

  ```js
  if (request.method === 'GET' && url.pathname.startsWith('/skills/') && url.pathname.endsWith('/')) {
    const assetRes = await env.ASSETS.fetch(request);
    if (assetRes.status === 200) return assetRes;
    const slug = url.pathname.slice('/skills/'.length, -1);
    return renderListedSkillPage(slug, env);
  }
  ```

- `renderListedSkillPage(slug, env)`:
  ```js
  async function renderListedSkillPage(slug, env) {
    const raw = await env.SKILLS_KV.get(slug);
    if (!raw) return new Response('Not found', { status: 404 });
    const skill = JSON.parse(raw);  // single ~9 KB record. Safe at any catalog size.
    return new Response(renderSkillHtml(skill), {
      headers: {
        'content-type': 'text/html; charset=utf-8',
        'cache-control': 'public, max-age=300, s-maxage=300',
      },
    });
  }
  ```
- **Per-request memory:** one ~9 KB string + one parsed object. Independent of catalog size.
- **KV read latency:** ~10-30 ms cold per Cloudflare docs; cached within isolate after first read of the same key.
- **5-min HTML edge cache** means popular Listed slugs are served from edge cache after first dynamic render.

**Why this works at any catalog size:**
- No NDJSON materialization in worker. No `res.text()` on full file. No `.split('\n')`.
- The 80k catalog wall referenced in Rev 1 is **eliminated**.
- KV value size cap is 25 MiB per Cloudflare; a single skill record is ~9 KB — comfortable.

### Publish:kv cost analysis (R11 context)

Workers KV free tier (retrieved 2026-05-18 from
https://developers.cloudflare.com/kv/platform/limits/):

| Limit | Free | Paid ($5/mo Workers Paid) |
|---|---|---|
| Reads/day | 100,000 | 10,000,000 |
| Writes/day | 1,000 | 1,000,000 |
| Storage | 1 GB | 1 GB included + $0.50/GB after |
| Value size | 25 MiB | 25 MiB |

Current site traffic: ~3,600 visits / 30 days = ~120 visits/day (CLAUDE.md).
At 10× growth (1,200 visits/day) with ~50% landing on a skill page, the KV
read volume is ~600/day → free tier comfortable.

Write side is the binding constraint at first bootstrap:
- **First publish (50k records):** 50k writes — overflows free tier in one
  day. Workaround: shard the initial bootstrap across multiple days
  (10k/day × 5 days) OR pay $5/mo for one month to absorb the bootstrap.
- **Steady state daily delta:** ~500 records/day per the SESSION-MEMO
  ~5 MB/day growth at 9 KB/record → comfortably under 1000/day free cap.
- **Incremental writes via content_sha comparison:** the publish:kv step
  diff against a sidecar `data/kv-published.json` mapping `slug → content_sha`
  and only upserts changed records. Sidecar is committed.

**Decision:** absorb one-time bootstrap cost. Either run the publish:kv step
across 5 daily runs (toggle env `KV_PUBLISH_BUDGET=10000`) or pay $5 for a
month to unblock bootstrap. Document the choice when T5 ships.

**Local dev:** `wrangler dev` includes a local KV stub. A small helper
script `scripts/lib/dev-kv-seed.js` seeds the local KV namespace from
`data/skills.ndjson` (reads line-by-line via streaming, calls `wrangler kv
key put --binding=SKILLS_KV` per record OR uses the bulk endpoint). T5 §5d
documents this for local development. CLAUDE.md gets a "Local KV dev"
subsection.

       ```js
       // Streams data/skills.ndjson line-by-line, computes content_sha,
       // compares against data/kv-published.json sidecar, and upserts only
       // changed records via Cloudflare KV bulk API (10k keys per request).
       //
       // Env vars: CF_API_TOKEN, CF_ACCOUNT_ID, SKILLS_KV_NAMESPACE_ID
       //
       // KV_PUBLISH_BUDGET env var (default 10000) caps writes per invocation.
       // First-bootstrap publish exceeds free-tier 1k/day cap; shard across
       // 5 daily runs OR run under Workers Paid for one month. See PLAN §
       // "Publish:kv cost analysis" for details.
       //
       // Exports: publishSkillsToKv(ndjsonPath, sidecarPath)
       export async function publishSkillsToKv(ndjsonPath, sidecarPath) {
         const prior = existsSync(sidecarPath) ? JSON.parse(readFileSync(sidecarPath,'utf-8')) : {};
         const budget = parseInt(process.env.KV_PUBLISH_BUDGET || '10000', 10);
         const changed = [];
         // Stream via readNdjsonRecords (memory-bounded)
         for (const [slug, record] of readNdjsonRecords(ndjsonPath, { keyFn: r => r.slug })) {
           const sha = computeContentSha(record);
           if (prior[slug] !== sha) {
             changed.push({ key: slug, value: JSON.stringify(record) });
             prior[slug] = sha;
             if (changed.length >= budget) break;
           }
         }
         // Bulk write in batches of 10k
         for (let i = 0; i < changed.length; i += 10000) {
           const batch = changed.slice(i, i + 10000);
           const res = await fetch(
             `https://api.cloudflare.com/client/v4/accounts/${process.env.CF_ACCOUNT_ID}/storage/kv/namespaces/${process.env.SKILLS_KV_NAMESPACE_ID}/bulk`,
             {
               method: 'PUT',
               headers: { 'Authorization': `Bearer ${process.env.CF_API_TOKEN}`, 'Content-Type': 'application/json' },
               body: JSON.stringify(batch),
             }
           );
           if (!res.ok) throw new Error(`KV bulk write failed: ${res.status} ${await res.text()}`);
         }
         writeFileSync(sidecarPath, JSON.stringify(prior, null, 2));
         console.log(`[publish:kv] upserted ${changed.length} changed records (budget: ${budget})`);
       }
       ```
       package.json: `"publish:kv": "node -e 'import(\"./scripts/lib/publish-kv.js\").then(m=>m.publishSkillsToKv(\"data/skills.ndjson\",\"data/kv-published.json\"))'"`.
