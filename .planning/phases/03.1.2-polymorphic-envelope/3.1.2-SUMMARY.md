# Phase 3.1.2 — Polymorphic Entity Envelope: READY TO MERGE

The pipeline can now host plugins, MCPs, frameworks, and any future entity type by adding a recipe + scorer + filter-rule pack — no core plumbing changes. The data model reshape that Phase 3.2 (plugin scoring) was blocked on is done.

**Cutover happens automatically on the first post-merge daily-scrape (6:30 AM UTC the day after merge).** See `3.1.2-CUTOVER.md` for the D+0 → D+7 sequence.

## Headline outcomes

| Capability | Pre-F2 | Post-F2 |
|---|---|---|
| Data model | Flat `SkillRecord` only | Polymorphic `EntityRecord` discriminated union (6 entity_types) |
| Classifier | Rigid `category` string (7 enum values) | `tags: string[]` with namespaces (`category:*`, `framework:*`, `integration:*`, `language:*`, `source:*`); legacy `category` retained through 3.6 |
| Scoring | Single `scoreSkill` function in `score.js` | Type-aware registry at `scripts/lib/scorers/index.js`; current logic isolated in `skill.scorer.js` |
| Filter | Monolithic `filter.js` rules | Type-aware registries at `scripts/lib/filter-rules/{common,skill}.rules.js` + dispatcher |
| Scraping | Skill-specific 679-line `scrape.js` | Recipe shape at `scripts/lib/recipe-engine.js` ready for plugin recipes (scrape.js delegation deferred to 3.2) |
| Vectorize metadata | tier + category | tier + category + **entity_type** (parsed additively in worker triad filter) |
| Embedding input builder | Inline in `embed-skills.js` | Same (functional equivalent; `scripts/embedding-input/` not extracted, documented as deferral) |
| NDJSON header | Optional | Required, contains `schema_version: 2` + `entity_type` sentinel |
| Read path | Flat fields via `src/lib/skills.js` | Polymorphic `src/lib/entities.js` loader with `legacy-skill-reader.js` upcaster for v1 records; `skills.js` is a 30-line re-export shim |

## Lessons learned

1. **Pre-F2 data quirks > strict F2 invariants.** The body_length invariant was correct in principle (any F2 logic mutating body_length should fail loudly) but didn't account for pre-F2 scraper trim behavior. Future invariants should explicitly enumerate which writers/versions are subject to them.

2. **Dual-read upcaster + production-scale branch CI = sufficient validation.** Phase 3.1's "single-file-pattern" cascade was driven by scale-dependent surprises. This phase's risk was shape divergence between consumers, which the upcaster property test + branch CI dispatch caught comprehensively. No deploy cascade this time.

3. **Branch CI dispatches are the right safety net.** Once Phase 3.1 added branch guards (PR #5), branch CI dispatches became a free production-scale smoke. Phase 3.1.2 ran two dispatches (one failed at body_length, one passed) without ever touching production. This pattern carries forward.

4. **Polymorphic envelope sets up Phase 3.2 for a clean ship.** Plugin scoring + filtering can now ride on the registries — no schema changes, no pipeline refactors. The phase plan promised this; the verifier confirmed it.
