# F2 Plan Check

## Verdict

**BLOCK.** The plan is thorough on shape, recipe abstraction, and upcaster strategy, but it has **six BLOCKERs** that fall squarely into the "did we miss a consumer" failure mode the prompt foregrounds. Three production scripts that mutate the legacy skill shape are absent from `files_modified` (`scripts/backfill-skill-birth-dates.js`, `scripts/scrape-discover-repos.js`, `scripts/generate-badges.js`); the Astro+TS verification harness the plan relies on (`npx astro check`) requires packages that aren't installed (`@astrojs/check`, `typescript`) — R1's mitigation is therefore a no-op as written; the F1↔F2 contract on `_header` NDJSON sentinels conflicts with F1's plan as currently written (F1 does NOT add header support, and worse F1's `loadAllSkillsSync` would treat a header line as a fake skill); the `worker/index.js` migration silently drops `tier` filtering behavior (F2 only enumerates `category` + `type`); DOD-9/DOD-10 are declared but never given verify hooks that pre/post-diff sitemap URLs; and the production data mutation (Task 9 in-place migration + release-asset re-publish) runs BEFORE the smoke gate (Task 11) that's intended to catch shape regressions.

## BLOCKERs

### B1 — Three production scripts that read/write the legacy skill shape are absent from `files_modified`

- **Where:** PLAN.md lines 8–55 (`files_modified` list). Grep against `src/`, `scripts/`, `worker/` for `skill\.(body_markdown|frontmatter|has_name|has_description|skill_path|skill_first_commit_at)` plus writes of those keys returns hits in:
  - `scripts/backfill-skill-birth-dates.js:172,179,181,185,189,191` — reads/writes `skill.skill_first_commit_at`, `skill.skill_path`. NOT in `files_modified`.
  - `scripts/scrape-discover-repos.js:209-214` — constructs records with flat `skill_path`, `frontmatter`, `body_markdown`, `has_name`, `has_description`. NOT in `files_modified`. This script is itself a Track-2 discovery path — arguably should be folded into the new recipe pattern alongside `scripts/scrape.js`.
  - `scripts/generate-badges.js` — matched on legacy-shape grep. NOT in `files_modified`.
- **Why it's a BLOCKER:** this is the exact "did we miss a consumer" failure mode the CONTEXT.md focus and F1 plan-check B4 explicitly named. On D+0 of cutover, the daily-cron runs `scrape-discover-repos.js` which emits **flat v1 records** into `data/skills-raw.ndjson` while the rest of the pipeline now writes v2.

### B2 — `npx astro check` is invoked as a gate but the toolchain isn't installed

- **Where:** Task 1 verify, R1 mitigation, Approach §8 Smoke B, T11 Smoke B.
- **Problem:** `package.json` has no `@astrojs/check` and no `typescript`. The verify command `npx astro check ... | grep -cE 'error TS' | grep -q '^0$'` returns 0 errors when the toolchain isn't present (grep sees nothing) — the gate passes vacuously. R1's mitigation is structurally unsound until the tooling is added.
- **Fix:** Add `@astrojs/check` + `typescript` to devDependencies as Task 1 step 0. Change verify to `npx astro check --noProgress; test $? -eq 0` — non-zero exit codes fail the gate.

### B3 — F1↔F2 contract on `_header` NDJSON sentinel is broken

- **Where:** Approach §7 lines 793–805, Task 1 `buildHeader()`, Task 5 verify, Open Question #1.
- **Problem:** F1's plan keys `readNdjsonRecords()` by `r.id` by default. A header record `{_header: true, schema_version: 2, ...}` has no `id` — F1's reader will Map-key it as `undefined`, then the next real record collide-overwrites that key. F1's `loadAllSkillsSync` would include the header as a fake skill, breaking `getStaticPaths()`.
- **Fix (one of):**
  1. F1 Rev 2 explicitly adds `_header` handling to `readNdjsonRecords`, `writeNdjsonStreaming`, and `loadAllSkillsSync`. (RECOMMENDED — keeps schema_version atomic with data.)
  2. F2 switches to a sidecar `data/skills.ndjson.meta.json` for schema_version.

### B4 — `worker/index.js` migration drops `tier` filter behavior

- **Where:** Today's `worker/index.js:253-258` accepts `filterTier` AND `filterCategory`. F2 plan Approach §2 worker row mentions only `entity_type`, `tags`, `category`. T8 step 5 enumerates `?type=` and `?category=` but not `?tier=`.
- **Why it's a BLOCKER:** if the planner replaces the `if (filterTier || filterCategory)` block instead of adding to it, `?tier=top` queries silently stop filtering server-side. Production search-quality regression with no surface error.
- **Fix:** T8 step 5 explicitly enumerates ALL existing filters: `tier` (keep), `category` (keep + add tag fallback), `type` (new). Regression set must include tier-filtered queries.

### B5 — DOD-9 and DOD-10 have no verify-step implementation

- **Where:** Plan frontmatter lines 67–68. No sitemap-diff smoke in Approach §8 or T11's seven commands.
- **Fix:** Add to T7 verify (or new T11 smoke): build twice (pre/post F2), then diff sitemap URLs. Capture pre-F2 sitemap URL list in T2. Success criterion: "Every URL in pre-F2 sitemap-0.xml responds HTTP 200 on the post-F2 preview deploy."

### B6 — Task 9 mutates production data BEFORE Task 11's smoke gate

- **Where:** T9 runs the live migration + commits + re-publishes release asset. T11 is the smoke gate AFTER T9.
- **Why it's a BLOCKER:** if T11's smoke finds a missed consumer (per B1), the production `data/skills.ndjson` is already v2 and the release asset is already re-published. No clean rollback.
- **Fix:** Reorder. T11 smoke suite runs BEFORE T9 production migration. T9 tags previous release asset `skills-latest-prev` before publishing. Mirrors F1's rollback-safety pattern.
