## Goal-Backward Summary

**Will executing this plan as written achieve the phase goal?**

**Conditional yes - IF the 3 blockers are resolved before execution.**

The architecture passes goal-backward analysis at every level:
- Track 2 uses /search/repositories (correct API per RESEARCH.md Q3b/Q8c)
- skills-raw.json persists via GHA cache + release-asset bootstrap (proven pattern)
- Filter has graceful fallback so Track-1-only days never red-X CI
- Weekly safety net stays on code search to catch untagged-repo SKILL.md files
- Smoke harness catches the wiring class of bugs (tied to 3.0.0 burn modes)
- 11 risks (R1-R11) explicitly enumerated with mitigations

What could still go wrong:
1. The Task-1/Task-4 export-refactor split (concern #9) creates Wave-2 wiring fragility - if executor strictly does Task 1 first, the script ships without exports and Task 4 patches it. Works, but invites bugs.
2. Concern #11: a downstream consumer filtering on source could silently drop new Track 2 records with source = discover. 10-second grep needed before merge.
3. R9 (1000-cap saturation warning) is documented but not implemented in code - silent failure mode lurks if a topic ever crosses 1000.

The 4 specific 3.0.0 burns this plan must NOT repeat:
- pushed:> not filtering on code search - resolved by Decision A (repo search)
- V8 string limit on stringify - not relevant for skills-raw at 295 MB; etag streaming already shipped in 82cc7ab
- skills-raw.json gitignored vs runner-needed - resolved by Decision E (GHA cache + release bootstrap)
- Low ETag hit rate across multi-day windows - RESEARCH.md Q3a re-frames as 304s do not count against primary RL, removing the binding constraint. Plan inherits this.

## Required Revisions (BLOCKERS)

1. **Concern #9 - Move the export keywords plus isMain guard into Task 1 source spec.** As written, Task 1 ships scrape-discover-repos.js with plain async function listSkillPaths etc., and Task 4 retrofits exports. This invites Wave-2 brokenness if Task 1 lands without Task 4 also landing. Cleaner: Task 1 emits the script in final shape (with exports plus isMain guard) from the start. Task 4 then only needs to import.

2. **Concern #14 - Implement the R9 saturation warning in searchTopic.** R9 risk register says log a warning when any topic returns exactly 1000 (signal to narrow window or split by qualifier) but actual searchTopic implementation (372-391) just breaks. Add a check at the end of pagination: if last page hit max items AND we hit MAX_PAGES_PER_TOPIC, warn that long-tail repos may be missed today (weekly sweep catches them).

3. **Concern #21 - Extend CLAUDE.md data model type union to include discover.** Task 8 currently adds 4 new facts but does not update the source field documented values. New Track 2 records will have source = discover not in the documented code-search / topics / seed union. Update CLAUDE.md line 79 to add discover. Trivially append.
