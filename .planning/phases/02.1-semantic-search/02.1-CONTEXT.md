# Phase 2.1: Semantic Search - Context

**Gathered:** 2026-04-11
**Status:** Ready for planning (autonomous post-1.5.1 run)
**Parent milestone:** 2.0 — Agent-Native Directory

<domain>
## Phase Boundary

Replace the homepage's keyword substring search with true semantic search over skill content. Users can type natural-language queries like "testing frameworks for python" or "review my pull requests" and get ranked results by meaning, not keyword overlap.

Ship a public query API at `/api/v1/search` so agents and tools can call ClaudeAtlas as infrastructure rather than just browse it as a site.
</domain>

<decisions>
## Implementation Decisions

### Stack
- **Embedder:** OpenAI `text-embedding-3-small` @ 1536 dimensions (default)
  - Cheapest viable model ($0.02 / 1M tokens)
  - 1,078 skills × ~400 tokens = ~$0.009 for a full cold embed
  - Delta runs only embed changed skills (SHA-based diff)
- **Vector DB:** Cloudflare Vectorize, cosine metric, 1536 dims
  - Index: `claudeatlas-skills`
  - Free tier: 5M queried vectors/month, 30M stored — nowhere near the cap
  - Native to the existing Workers deployment — no new platform
- **Query-time embedding:** OpenAI API called from the Worker (Cloudflare edge → OpenAI → back)
  - Adds ~1-1.5s to query latency
  - Optimization path: cache common query embeddings in Workers KV (Phase 2.2)

### Vector IDs
- Use `skill.id` (not `skill.slug`) as the Vectorize key
- Why: 6 skills in the current catalog share a slug because two repos host the same skill name (e.g. `microsoft/skills/azure-aigateway` and `microsoft/azure-skills/azure-aigateway`). `skill.id` is globally unique per catalog entry.
- Vectorize has a 64-char id limit; long ids get hashed to `sk_<40 hex>`.
- `metadata.slug` still carries the slug for display + detail page routing.
- `/api/v1/search` dedupes by slug on return so the 6 collision pairs show up as a single result.

### UX replacement vs dual-mode
- **Replace**: the homepage's sticky search input now calls `/api/v1/search` instead of filtering DOM substrings.
- Fall-back to substring-filter keyword mode if the API errors (e.g. Vectorize binding missing on a preview deploy).
- No second `/search` page — single mental model.

### CI integration
- `embed-skills.js` runs on every workflow event (push + scheduled + manual) after the filter step.
- Content SHA diff means unchanged skills aren't re-embedded.
- `upload-vectors.js` upserts the ndjson into Vectorize on every run.
- Both steps are idempotent; re-running does nothing expensive.

### File format
- `data/skill-vectors.ndjson` is committed to git as a content-addressable cache (~32 MB).
- Line-per-vector NDJSON format directly compatible with Vectorize bulk insert.
- Fingerprint: each record has `metadata._content_sha` which is the SHA-256 of the fields used to build the embedding input.
</decisions>

- "testing frameworks for python" — testing + language match
- "review my pull requests" — PR review tools

<deferred>
## Deferred Ideas

Not in this phase, for 2.2+:
- **Query cache** in Workers KV (embeddings of top 100 queries cached for 24h) — would drop query latency from ~1.5s to ~0.5s on cache hits
- **"Similar skills" enrichment** on skill detail pages (pre-computed top-5 from the same vector space at build time)
- **Clustering** on the vector space to surface emergent categories / detect miscategorized skills
- **Hybrid search** (semantic + keyword with reciprocal rank fusion) — probably unnecessary at our scale
- **Tier / category filter UI** on the homepage search (API already supports them, just needs chips)
- **Query history** in PostHog cohort analysis
- **marketplace.json federation** — make the query API the search backend for Claude plugin clients

Also deferred: the **slug collision bug** itself. The canonical fix is to make `getCategorySlug` / the slug-computation step path-aware when there's a conflict (e.g. `microsoft/azure-aigateway` becomes `microsoft/skills/azure-aigateway` vs `microsoft/azure-skills/azure-aigateway`). That requires a scraper/filter change + full re-scrape to validate, so it's Phase 1.5.2 material. For now, `/api/v1/search` dedupes by slug on the way out and the 6 collision-pair twins share a detail page (the last-wins Astro rendering behavior from Phase 1).
</deferred>
