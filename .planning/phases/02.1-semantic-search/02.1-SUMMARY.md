# Phase 2.1: Semantic Search — Summary

## What shipped

Real semantic search over skill content, live at `https://claudeatlas.com`. Users type natural-language queries on the homepage and get meaning-based results. Agents can hit `/api/v1/search` directly to discover skills programmatically.

| Rank | Score | Skill | Why |
|---|---|---|---|
| 1 | 0.54 | claude-code-review | literally "Use when asked to review a PR" |

- **Initial embed cost:** $0.0086 (432k tokens across 1,078 skills)

- **Total monthly cost:** $0 after the one-time $0.0086

## Key technical decisions

1. **`skill.id` not `skill.slug`** as the Vectorize vector key — 6 slug collisions in the catalog forced this. Discovered during run #11 failure and fixed in commit 2357153.
2. **Replace keyword search** rather than dual mode — single mental model, instant-fallback keyword filter on API error means rollback is automatic
3. **EU PostHog + Cloudflare for compliance hygiene** + **OpenAI in the US for cheapest embedding** — acceptable tradeoff; only query text (not identifiers) crosses to OpenAI
4. **Commit the NDJSON cache** — saves ~$3/year in CI embed cost, keeps re-runs fast, makes local dev reproducible
5. **Dedupe on API return** — the 6 slug collisions show as a single result (highest-scoring twin wins) so the homepage doesn't render visible duplicates

## Known gaps / deferred

- **Query latency is ~1.5s** — dominated by OpenAI embedding round trip from Cloudflare's edge. Query cache in Workers KV would drop this to ~500ms on cache hits. Phase 2.2 if needed.
- **Slug collision bug** still exists at the data layer (6 pairs of skills sharing a slug). The canonical fix is to make slug computation path-aware in `scripts/filter.js`. Filed as Phase 1.5.2 but not blocking — `/api/v1/search` dedupes on return.
- **No tier/category filter UI** on the homepage — API supports them via query params, just needs chips. Small follow-up.
- **No "similar skills" section on detail pages** — would use the same vector space, pre-computed at build time. Natural Phase 2.2 work.
- **No rate limiting** on `/api/v1/search` — Cloudflare Workers includes basic DDoS protection but nothing stops a malicious actor from burning OpenAI credits. Worth adding Cloudflare Rate Limiting rules or a KV-based per-IP counter if this becomes a problem.
