<domain>
## Phase Boundary

This phase makes `api` records REAL: a daily harvester pulls the four open API catalogs, a filter merges/scores/tiers them, and the embed → enrich → upload-vectors legs run for them behind `DATA_FEEDS_ENABLED`. After this phase ships:

- `scripts/harvest-apis.js` writes `data/apis-raw.ndjson` (GHA-cached, `_header` sentinel) from APIs.guru, data.gouv.fr dataservices, the UK co-cddo api-catalogue CSV, and the marcelscruz public-apis mirror — ≈ 6–7k raw records.
- `scripts/filter-apis.js` writes `data/apis.ndjson` (cross-source merge by primary host, rule packs, `api.scorer.js`, percentile tiers, `assignSlugs`, `PRESERVED_FIELDS`) and an `api` section in `data/pipeline-stats.json`.
- `embed-skills.js --entity-type api`, `enrich.js` (dedup ON for api), and `upload-vectors.js` handle `data/api-vectors.ndjson`; `/api/v1/search?type=api` therefore returns results (no UI exposes it yet — that is 4.3).
- `daily-scrape.yml` gains the steps above, every one gated on `env.DATA_FEEDS_ENABLED == 'true' && github.event_name != 'push'`, plus an `apis-latest` release asset mirroring `plugins-latest`; `DATA_FEEDS_ENABLED` stays `'false'` on main until the branch-measured run is green (flip is the last task, same pattern as 3.4).
- A calibration report (`4.2-CALIBRATION.md`) records the first real tier distribution for Dan to eyeball; scorer weights stay as the spec unless he changes them.

**Out of scope (later phases):** pages, nav, search chips, KV publish of Listed-tier api records (4.3); reachability probe + header sniffing (4.4); datasets (4.5); consumer graph (4.6); heuristic/LLM access extraction and overrides (4.7); GitHub code-search spec discovery (4.8).

**Why this phase, why now:** 4.1 made the envelope total for `api`; the shortest path to something Dan can see is real records in the search index and a tier distribution to react to. Dan chose APIs-first on 2026-11-02.

</domain>

<decisions>
## Implementation Decisions

### D-01: Four sources, exactly these, with these roles
| Source | Access | Role | License |
|---|---|---|---|
| **APIs.guru** | `https://api.apis.guru/v2/list.json` (8.8 MB) + the `x-preferred` version's `swaggerUrl` per API | **canonical** record when present (has the spec) | CC0 |
| **data.gouv.fr dataservices** | `https://www.data.gouv.fr/api/1/dataservices/?page_size=200` paginated (`next_page`) | contributes `rate_limiting`, `access_type`, `availability`, `license`, `base_api_url`, `machine_documentation_url` | Licence Ouverte 2.0 |
| **UK co-cddo/api-catalogue** | raw `data/catalogue.csv` from GitHub (`raw.githubusercontent.com/co-cddo/api-catalogue/main/data/catalogue.csv`) | contributes docs URL, license, maintainer, provider | OGL v3 |
| **marcelscruz/public-apis** | raw `db/resources.json` | coarse `Auth` / `Cors` / `Link` / `Category`; broad consumer-facing coverage | MIT |
RapidAPI, Postman, APIs.io and GitHub code search are explicitly NOT sources in this phase (ToS or 4.8).

### D-02: Harvester mechanics
- One script `scripts/harvest-apis.js`, two passes: (1) catalog pass — fetch the four listings, emit one raw record per listing entry; (2) spec pass — for APIs.guru entries only, fetch the preferred-version OpenAPI JSON and extract `info.{title,description,license,termsOfService,contact,version}`, `servers[].url` (or swagger `host`+`basePath`+`schemes`), `components.securitySchemes` / swagger `securityDefinitions`, `paths` count, response media types, `x-apisguru-categories`, `x-origin`, `x-unofficialSpec`, `externalDocs`. **Never store the whole spec.**
- Politeness: UA `ClaudeAtlasBot/1.0 (+https://claudeatlas.com/bot)` (reuse `AGENT_UA` from `scripts/lib/reciprocal-probe.js`), concurrency ≤ 4, ≥ 250 ms between requests to the same host, 20 s timeout, 3 retries with backoff on 429/5xx.
- Conditional fetching: ETag / Last-Modified cache sidecar `data/feeds-etag-cache.json` (bounded: one entry per URL, ≈ 5k entries) so warm runs are mostly 304s. Spec pass re-fetches a spec only when list.json's `updated` for that API changed since the cached raw record, or the raw record is missing.
- Size guard: skip spec bodies > 5 MB (record `spec_url`, set `extra.spec_parsed = false`); the azure/google mega-specs are the known offenders.
- Output `data/apis-raw.ndjson` via `writeNdjsonStreaming` (tmp + rename), header `buildHeader('api')`. Raw record shape = the fixture shape from 4.1 (`data/__fixtures__/apis-mini.ndjson`), i.e. what `upcastApiRecord` expects, plus `raw_source` for debugging (dropped by the upcaster).
- Checkpoint saves every 500 records; `--mode=catalog-only` and `--limit N` flags for smoke runs; exits non-zero if ANY of the four sources returned zero entries (a silent zero is the failure mode we care about).

### D-03: Cross-source merge (in filter-apis.js, before scoring)
- Merge key = `canonicalHost(primary base URL or Link) + '/' + nameStem`, where `canonicalHost` strips a leading `www.` / `api.` / `developer.` and lowercases, and `nameStem` is the slugified name with trailing ` api` / `-api` removed. If no base URL is known, key on the docs/Link host.
- Precedence: APIs.guru > data.gouv.fr > UK catalogue > public-apis. The winner supplies identity fields (`id`, `name`, `provider`, `base_urls`, `spec_url`); every loser's `origin.source` goes into `origin.also_listed_in` and its access fields are merged **only where the winner's value is `unknown`/null**, keeping each field's provenance.
- Embedding dedup (`enrich.js`) runs afterwards as for skills and will catch same-API-different-host cases; do not over-engineer the key.

### D-04: Access extraction v1 = ladder steps 1–2 only (spec + declared)
- `spec`: `securitySchemes` → `auth.type` (`apiKey`→`api_key`, `http` bearer→`bearer`, `http` basic→`http_basic`, `oauth2`→`oauth2`, `openIdConnect`→`openid`, none declared → `none`) confidence 0.9; `info.license` → `license` (spdx when the name maps, else `name`+`url`) 0.9; response media types → `formats` 0.8; `transport` = `'rest'` (or `'graphql'` when a `/graphql` path or `x-apisguru-categories` says so).
- `declared`: data.gouv.fr `rate_limiting` (free text → `rate_limit.notes`; parse `N per <unit>` into `requests`/`per` when it matches `^\s*(\d[\d,.]*)\s*(req|requests|calls|appels)?\s*(/|per|par)\s*(second|sec|s|minute|min|hour|h|day|jour|month|mois)` else leave numbers null) 0.8; `access_type` (`open` → `auth.type: none`, `restricted`/`open_with_account` → `api_key` if unknown) 0.7; `availability` ignored (4.4 owns reachability); `license` 0.9. public-apis `Auth` (`No`→`none`, `apiKey`→`api_key`, `OAuth`→`oauth2`, `X-Mashape-Key`→`api_key`, `User-Agent`→`none`) 0.6, only when still unknown. UK catalogue `license` 0.8.
- `cost.model`: `free` with provenance `declared` 0.7 for data.gouv.fr, UK catalogue and public-apis entries (all three catalogs list free/open APIs by charter); otherwise `unknown`. No heuristics, no LLM, no overrides file (4.7).

### D-05: filter-apis.js mirrors filter-plugins.js
Pipeline: read raw → merge (D-03) → `upcastRecord` → `isSlop` (api rule pack) → `scoreEntity` → `assignPercentileTiers` (10/30/60, within the api population; `RENDERABLE_CAP` is NOT applied to api in 4.2 because no pages exist) → `assignSlugs` → carry `PRESERVED_FIELDS` (`is_duplicate`, `canonical_id`, `canonical_slug`, `novelty_score`, `bundled_in_plugins`, plus `extra.consumed_by`) from the prior `data/apis.ndjson` → write `data/apis.ndjson` with header `buildHeader('api')` → write `pipeline-stats.json.api` (`total_raw`, `total_apis`, `by_source`, `merged_duplicates`, `tiers`, `access_clarity_histogram`, `timestamp`). Pre-flight: fail loudly below `MIN_API_RAW = 1000` raw records or if any source count is 0.

### D-06: Calibration is a report, not a blocking checkpoint
A task produces `.planning/phases/4.2-api-harvest-v1/4.2-CALIBRATION.md` from a real local run: tier counts, per-source counts before/after merge, top 20 / bottom 20 by score with their signal breakdown, access-clarity histogram, and the 10 highest-scored `unknown`-auth records. Weights stay at the spec table. Dan reviews after the fact; any retune becomes a `/gsd:quick`. Executors do not pause for human verification in this phase.

### D-07: Pipeline wiring (all behind `DATA_FEEDS_ENABLED`)
- New steps in `daily-scrape.yml`, placed after "Link bundles" and before "Embed skills", each with `if: ${{ env.DATA_FEEDS_ENABLED == 'true' && github.event_name != 'push' }}`: Restore apis-raw cache (`apis-raw-ndjson-*`) → Run API harvest → Save apis-raw cache (`always()`) → Filter APIs → Embed APIs (`--entity-type api`, input `data/apis.ndjson`, output `data/api-vectors.ndjson`, cached like plugin vectors) → Enrich APIs (`--entity-type api`, dedup ON) → upload-vectors loop gains `data/api-vectors.ndjson` → "Publish apis-latest release asset" (main-only, mirrors plugins-latest incl. `-prev` tagging) → push-event path "Fetch apis-latest" (`continue-on-error`).
- `embed-skills.js`, `enrich.js`, `upload-vectors.js` must accept `api` wherever they dispatch on entity type today (follow the plugin precedent; `buildEmbeddingInput` already handles it).
- Build: `src/lib/entities.js` loads `data/apis.ndjson` when present (same optional-file pattern as plugins) so `getEntitiesByType('api')` works for 4.3; no page reads it yet. `generate-llms-txt.js` and `snapshot-catalog.js` may count apis if trivially additive, otherwise leave for 4.3.
- Flag flip: the LAST plan measures a branch dispatch (`gh workflow run daily-scrape.yml --ref feat/v4.0-data-feeds` with `DATA_FEEDS_ENABLED` forced on via a workflow_dispatch input if one exists, else a temporary branch-only env change) and records wall time per new step. Flip `DATA_FEEDS_ENABLED` to `'true'` only if the measured run is green and the total projected cron stays under the 330-minute ceiling; otherwise leave `'false'` and document the gap (3.3-07 precedent).

### D-08: Untouched in 4.2
Reachability (stays neutral 70), `consumed_by` (stays empty), pages/search UI, KV publish, datasets. `scripts/filter.js`, `scripts/score.js`, skill/plugin tier percentages and `RENDERABLE_CAP` are not modified.

### D-09: Budget and cost guards
- Harvest: ≈ 1 list.json + ≤ 2.6k spec GETs cold (ETag-cached after), ≈ 7 data.gouv.fr pages, 2 raw GitHub files. Expected cold wall time < 20 min at concurrency 4, warm < 5 min. A cron-audit note in the final SUMMARY records the measured numbers.
- Embedding: ≈ 7k records × ≈ 250 chars one-time ≈ cents; CI and plan-check runs use `EMBED_DRY_RUN=1`; the live-key smoke happens once on the branch dispatch.
- Vectorize: +≈ 11M stored dims ≈ +$0.006/month (verified 2026-11-02 pricing). KV: none in 4.2.

### D-10: Tests and fixtures
- Parsers are pure functions with fixtures captured from REAL responses (trimmed): one APIs.guru list.json slice (≥ 5 APIs incl. one with `x-unofficialSpec`), one OpenAPI 3 spec and one Swagger 2 spec (securitySchemes / securityDefinitions, servers vs host+basePath), one data.gouv.fr page (≥ 3 dataservices incl. a `rate_limiting` string), a 10-row UK CSV, a 10-entry public-apis resources.json. Fixtures live under `data/__fixtures__/` (4.1 precedent) and are allowlisted for `readFileSync` in tests.
- Unit tests for: each source parser, `canonicalHost`/merge key, precedence merge with provenance preservation, rate-limit string parser, auth mapping, pre-flight floors, PRESERVED_FIELDS carry-over, pipeline-stats shape. Integration: filter-apis on the fixture raw set end to end. `npm test` baseline after 4.1: 535 / 527 / 2 (pre-existing embed-skills) / 6; `check:patterns` clean; legacy-shape lint 5.
- Network calls are never made in tests; `harvest-apis.js` takes an injectable `fetch` for the smoke test.

### D-11: Fixture / slug follow-ups from 4.1
Extend `data/__fixtures__/apis-mini.ndjson` only if a new raw field is required by the harvester (keep the 4.1 round-trip green). Pitfall from 4.1 research: `BIZ_SLOP_PATTERNS` may false-positive on real API names — the calibration report must list any records dropped by `hasBizSlopName` so Dan can decide whether to exempt the api rule pack from that list.
