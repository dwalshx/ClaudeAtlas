# Phase 4.2 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Derived from `04.2-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node built-in `node:test` + `node:assert/strict` |
| **Config file** | none — glob in `package.json` `"test"` (new files under `scripts/lib/feeds/__tests__/`, `scripts/__tests__/`, `src/lib/__tests__/` are picked up automatically) |
| **Quick run command** | `node --test scripts/lib/feeds/__tests__/<file>.test.js` |
| **Full suite command** | `npm test` |
| **Lint gates** | `npm run check:patterns` → `lint mode: clean (0 baselined, 0 new)`; `node scripts/lint-no-legacy-skill-shape.js` → exactly `5 legacy-shape hit(s)` |
| **Estimated runtime** | ~4-5 seconds |

**Baseline (re-measured 2026-11-05 @ `b96e9bf`):** `# tests 535 / pass 527 / fail 2 / skipped 6`; the 2 fails are the pre-existing `scripts/__tests__/embed-skills.test.js:74` and `:88` (PR dwalshx/ClaudeAtlas#24 rewrites them on main; if it merges and the branch rebases, the baseline becomes `fail 0` with 1 extra test). Exit criterion: no NEW failures; `pass` = baseline pass + new tests.

**Network rule:** no test performs a real HTTP request. Harvester and fetch helpers take an injectable `fetchImpl`.

---

## Sampling Rate

- **After every task commit:** the task's own test file(s) via `node --test <file>` + `npm run check:patterns`
- **After every plan wave:** `npm test` + both lints
- **Before `/gsd:verify-work`:** full suite at baseline, lints clean, `git diff --stat -- scripts/filter.js scripts/score.js` empty, `git status` shows no `data/apis*` or sidecar files
- **Max feedback latency:** 10 seconds
