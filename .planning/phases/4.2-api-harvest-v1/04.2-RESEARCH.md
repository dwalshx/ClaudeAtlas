#### D-02: Harvester mechanics
- One script `scripts/harvest-apis.js`, two passes: (1) catalog pass — fetch the four listings, emit one raw record per listing entry; (2) spec pass — for APIs.guru entries only, fetch the preferred-version OpenAPI JSON and extract `info.{title,description,license,termsOfService,contact,version}`, `servers[].url` (or swagger `host`+`basePath`+`schemes`), `components.securitySchemes` / swagger `securityDefinitions`, `paths` count, response media types, `x-apisguru-categories`, `x-origin`, `x-unofficialSpec`, `externalDocs`. **Never store the whole spec.**
- Politeness: UA `ClaudeAtlasBot/1.0 (+https://claudeatlas.com/bot)` (reuse `AGENT_UA` from `scripts/lib/reciprocal-probe.js`), concurrency ≤ 4, ≥ 250 ms between requests to the same host, 20 s timeout, 3 retries with backoff on 429/5xx.
- Conditional fetching: ETag / Last-Modified cache sidecar `data/feeds-etag-cache.json` (bounded: one entry per URL, ≈ 5k entries) so warm runs are mostly 304s. Spec pass re-fetches a spec only when list.json's `updated` for that API changed since the cached raw record, or the raw record is missing.
- Size guard: skip spec bodies > 5 MB (record `spec_url`, set `extra.spec_parsed = false`); the azure/google mega-specs are the known offenders.
- Output `data/apis-raw.ndjson` via `writeNdjsonStreaming` (tmp + rename), header `buildHeader('api')`. Raw record shape = the fixture shape from 4.1 (`data/__fixtures__/apis-mini.ndjson`), i.e. what `upcastApiRecord` expects, plus `raw_source` for debugging (dropped by the upcaster).
- Checkpoint saves every 500 records; `--mode=catalog-only` and `--limit N` flags for smoke runs; exits non-zero if ANY of the four sources returned zero entries (a silent zero is the failure mode we care about).

#### D-03: Cross-source merge (in filter-apis.js, before scoring)
- Merge key = `canonicalHost(primary base URL or Link) + '/' + nameStem`, where `canonicalHost` strips a leading `www.` / `api.` / `developer.` and lowercases, and `nameStem` is the slugified name with trailing ` api` / `-api` removed. If no base URL is known, key on the docs/Link host.
- Precedence: APIs.guru > data.gouv.fr > UK catalogue > public-apis. The winner supplies identity fields (`id`, `name`, `provider`, `base_urls`, `spec_url`); every loser's `origin.source` goes into `origin.also_listed_in` and its access fields are merged **only where the winner's value is `unknown`/null**, keeping each field's provenance.
- Embedding dedup (`enrich.js`) runs afterwards as for skills and will catch same-API-different-host cases; do not over-engineer the key.

#### D-04: Access extraction v1 = ladder steps 1–2 only (spec + declared)
- `spec`: `securitySchemes` → `auth.type` (`apiKey`→`api_key`, `http` bearer→`bearer`, `http` basic→`http_basic`, `oauth2`→`oauth2`, `openIdConnect`→`openid`, none declared → `none`) confidence 0.9; `info.license` → `license` (spdx when the name maps, else `name`+`url`) 0.9; response media types → `formats` 0.8; `transport` = `'rest'` (or `'graphql'` when a `/graphql` path or `x-apisguru-categories` says so).
- `declared`: data.gouv.fr `rate_limiting` (free text → `rate_limit.notes`; parse `N per <unit>` into `requests`/`per` when it matches `^\s*(\d[\d,.]*)\s*(req|requests|calls|appels)?\s*(/|per|par)\s*(second|sec|s|minute|min|hour|h|day|jour|month|mois)` else leave numbers null) 0.8; `access_type` (`open` → `auth.type: none`, `restricted`/`open_with_account` → `api_key` if unknown) 0.7; `availability` ignored (4.4 owns reachability); `license` 0.9. public-apis `Auth` (`No`→`none`, `apiKey`→`api_key`, `OAuth`→`oauth2`, `X-Mashape-Key`→`api_key`, `User-Agent`→`none`) 0.6, only when still unknown. UK catalogue `license` 0.8.
- `cost.model`: `free` with provenance `declared` 0.7 for data.gouv.fr, UK catalogue and public-apis entries (all three catalogs list free/open APIs by charter); otherwise `unknown`. No heuristics, no LLM, no overrides file (4.7).

## Summary

Phase 4.2 has no library-selection problem: everything it needs (streaming NDJSON helpers, the `api` upcaster, scorer, rule pack, embedding builder, slug/tier helpers, `setAccessField`, `AGENT_UA`) already exists on the branch, and Node 20's built-in `fetch`/`AbortSignal.timeout`/`ReadableStream` cover the HTTP side. The work is (a) four pure parsers + one OpenAPI extractor, (b) a small polite HTTP layer with an ETag sidecar, (c) a merge step, (d) a `filter-apis.js` that is a near-verbatim clone of `filter-plugins.js`, and (e) workflow wiring that clones the plugin step blocks. `github-fetch.js` is NOT reusable (it hard-exits without `GITHUB_TOKEN`, sends GitHub auth headers to every host and stores whole response bodies in its cache); write the small `scripts/lib/feeds/http-fetch.js` instead.

The live verification changed several planning assumptions. Raw volume is **~6,030 records, not 7–8k**: the UK CSV is 231 records (its 1,794 physical lines are multi-line quoted descriptions), APIs.guru is 2,529, data.gouv.fr 1,281, public-apis 1,992. APIs.guru's hosted directory is a **2023-04 snapshot** (newest `updated` 2023-04-21; `added.rss` last item 2023-04-22; repo `APIs/` last commit 2024-03-01) so every APIs.guru record will score Freshness 5, while data.gouv.fr records (modified 2026) score 75–100 — with the spec weights this ranks French municipal OpenDataSoft "APIs" above Stripe/GitHub/OpenAI. HEAD requests return no `Content-Length` (brotli, chunked), so the 5 MB guard must count streamed bytes; three known specs exceed it (microsoft graph 33.7 MB, github 11.6 MB, ec2 7.8 MB) and stripe is 4.77 MB. data.gouv.fr returns **no ETag/Last-Modified**, so its 7 pages (~7 MB, ~45 s) are re-fetched every run. The existing gates bite hard: the 50-char description floor would drop ~744 APIs.guru + ~110 data.gouv.fr + ~849 public-apis records, and `HAS_BASE_URL_OR_SPEC` drops every public-apis-only record unless the harvester emits `base_urls: [Link]` — both are calibration findings the report must surface, not things to silently fix.

Operationally: main's daily cron has failed every day since 2026-09-28 (Track 2 gets `HTTP 401` from GitHub search → empty raw → "loaded 0 vector records" at Upload vectors; on 2026-11-04 Track 1's failure-ratio gate fired first). A plain branch dispatch of `daily-scrape.yml` therefore dies before the api steps run. The measurement plan should use a dedicated branch-only `measure-data-feeds.yml` that runs just the api legs, and the flag flip must wait for a green main cron (CONTEXT's "document the gap" branch applies).

**Primary recommendation:** build `scripts/lib/feeds/{http-fetch,openapi-extract,api-access,api-merge,sources/*}.js` as pure modules with fixture tests, clone `filter-plugins.js` → `filter-apis.js`, clone the plugin workflow blocks, add a `data_feeds` dispatch input, measure with a dedicated workflow, keep `DATA_FEEDS_ENABLED='false'`, and let `4.2-CALIBRATION.md` carry the per-source signal bias and per-gate drop counts to Dan.

### Pattern 1: The raw record contract (what `harvest-apis.js` must emit)
`upcastApiRecord` (`legacy-skill-reader.js:397-427`) is a **field whitelist**. It reads, in order of precedence `rec.extra.X ?? rec.X`: `base_urls` (string[]), `spec_url`, `spec_version`, `endpoint_count` (number), `categories_src` (string[]), `provider` (string), `status_page_url`, `sdks`, `source_modified_at`, `access_clarity`, `consumed_by`; and top-level: `id` (else computed `api:${hostOf(base_urls[0]) || provider}/${name}`), `name`, `description`, `slug`, `origin{kind,source,source_id,source_url,also_listed_in}`, `home_url`, `docs_url`, the 16 `repo_*` (null unless `repo_full_name` is truthy), `body_length`, `quality_score`, `quality_tier`, `novelty_score`, `is_duplicate`, `canonical_id ?? canonical_slug`, `scraped_at`, `content_sha`, `source` (default `'registry'`), `discovery_signals`, `bundled_in_plugins`, `content_flags`, `access` (partial, merged over `emptyAccess()` by `mergeAccess` — only known group keys survive, provenance normalised), `tags`, `category`. **Anything else — `raw_source`, `spec_parsed`, `endpoint_summaries`, `cors` — is dropped.** Coercions: `str()` keeps only strings (so `''` stays `''`, non-strings → null), `num()` finite numbers only, `arr()` keeps only string elements.

Consequences for the harvester:
- Emit `id` explicitly as `apiRecipe.computeId(rec)` after `base_urls` are final, so the raw id equals the upcaster's and the recipes round-trip test's parity holds.
- Emit `docs_url: null` (not `''`) when unknown — `scoreFeedDocs` checks `typeof === 'string' && docs_url`, so `''` is harmless but `null` matches the fixture.
- `origin.kind`: `'registry'` for apis.guru and public-apis (fixture), `'portal'` for data.gouv.fr (fixture), `'registry'` for the UK catalogue; `origin.source` strings: `'apis.guru'`, `'data.gouv.fr'`, `'public-apis'` (fixture values) and `'uk-api-catalogue'` (new).

Otherwise derive "spec not parsed" as `spec_url && endpoint_count === null`. Recommendation: add both (≤10 × ~40 chars; ~1 MB total; the embedding builder already reads `endpoint_summaries`).

### Pattern 2: Polite HTTP layer (`scripts/lib/feeds/http-fetch.js`)
**What:** `politeFetch(url, { fetchImpl, etagCache, timeoutMs: 20000, maxBytes, accept })` → `{ status, notModified, body (string|null), headers }`; a `FetchPool(limit = 4, perHostMs = 250)` that serialises per-host spacing (all 2,529 specs live on ONE host, `api.apis.guru`, so the per-host gap is the throughput bound: 4/s → ~11 min cold); an `EtagCache` sidecar `data/feeds-etag-cache.json` of `{ [url]: { etag, last_modified, checked_at, status } }` — **no bodies** (the prior `data/apis-raw.ndjson` is the body cache for specs; the list/raw files are re-parsed when 200).
**Verified behaviours:** `api.apis.guru` honours `If-None-Match` (strong ETag on `list.json`, weak `W/"…"` on specs) and `If-Modified-Since` → 304 with empty body; `raw.githubusercontent.com` sends strong ETags (`Vary: Authorization`), `Cache-Control: max-age=300`; `www.data.gouv.fr` sends **no ETag / Last-Modified / RateLimit headers** (`cache-control: public` only) → always 200.
**Retries:** 3 attempts on 429/5xx/network with 1 s → 4 s → 16 s backoff, honour `Retry-After` seconds when present (cap 120 s like `github-fetch.js`). 4xx other than 429 → return as-is (no retry). Timeout via `AbortSignal.timeout(20000)`.
**Size cap:** HEAD is useless here (no `Content-Length`; `content-encoding: br`). Read `res.body.getReader()` and cancel once decoded bytes exceed `maxBytes` (5 MB), returning `{ capped: true }`. Measured: stripe 4.77 MB (under), microsoft graph 33.7 MB, github 11.6 MB, amazonaws ec2 7.75 MB (over); 40-spec stride sample p50 81 KB, p90 395 KB, mean 143 KB, ~370 MB total cold.

### Pattern 3: Harvester control flow (`scripts/harvest-apis.js`)
1. Parse args (`--mode=full|catalog-only`, `--limit N`, `--out <path>`); build `fetchImpl` (injected in tests).
2. Load prior raw (`readNdjsonRecords(OUT, { keyFn: r => `${r.origin.source}:${r.origin.source_id}` })`) and the ETag sidecar.
3. Catalog pass, in parallel across hosts but sequential per host: APIs.guru `list.json` (304 → re-parse? no body cached → on 304 **reuse prior raw records for the apis.guru source unchanged**; on 200 re-parse), data.gouv.fr pages 1..n via `next_page` (always 200; ~6 s/page), UK CSV, public-apis JSON. Each parser is pure and returns raw records.
4. Spec pass (skip in `catalog-only`): for each apis.guru raw record, if a prior record exists with the same `origin.source_id` and identical `extra.source_modified_at` (`v.updated`) and `spec_parsed !== null`, copy its spec-derived fields; else `politeFetch(swaggerUrl, { maxBytes: 5 MB })` → `extractOpenApi` → `applySpec`. `capped` → `spec_parsed: false`, `base_urls: []`, `endpoint_count: null`.
5. Checkpoint every 500 processed records to `data/apis-raw.ndjson.partial` via `writeNdjsonStreaming` (full rewrite — the file is ≤ ~10 MB) and save the sidecar; final `writeNdjsonStreaming(OUT, records, { header: buildHeader('api') })` + sidecar save.
6. Exit non-zero with a per-source table if any source yielded 0 records (and, defensively, if apis.guru < 2,000 or total < 1,000 — mirror `filter-mcps.js` MIN_* style). Print `by_source` counts and wall time per pass (the cron-audit note reads these lines).

### Pattern 4: Merge (`scripts/lib/feeds/api-merge.js`, called by `filter-apis.js` before upcast)
- `canonicalHost(url)`: lowercase hostname, strip ONE leading label from `www|api|apis|developer|developers|dev|docs|open|opendata|data|portal|sandbox|public` (discretion list; the extra labels matter because data.gouv.fr hosts are `data.*`/`opendata.*` and UK hosts are `api.service.hmrc.gov.uk`-style). Do NOT reduce to the registrable domain — `datarmor.cotesdarmor.fr` hosts 272 distinct dataservices and `azure.com` 653 APIs; the `nameStem` keeps them apart but a registrable-domain key would merge public-apis `github.com` listings (106) into one.
- `nameStem(name)`: NFKD-fold accents, slugify, strip leading `api-` and trailing `-api`.
- Key: `${canonicalHost(base_urls[0] ?? home_url ?? docs_url)}/${nameStem(name)}`.
- Group by key; sort each group by source precedence then by `source_modified_at` desc then `origin.source_id`; winner = first. Losers: push `origin.source` into winner `origin.also_listed_in` (dedupe); for each access path `auth.type`, `cost.model`, `cost.free_tier`, `rate_limit.requests/per/notes`, `license.spdx/name/url`, `formats`, `transport` fill ONLY if winner is `unknown`/null/`[]`, copying the loser's provenance entry for that path; fill `docs_url`, `extra.spec_url`, `extra.categories_src` (union) the same way. Count `merged_duplicates` = records − groups, split into `cross_source` and `same_source`.
- Measured expectations: same-source collisions — APIs.guru 8 keys (e.g. `insee.fr/metadonnees`-style duplicates are on the gouv side: 11 keys such as `data.ademe.fr/base-carbone` ×2), so same-source merging must be deterministic and never drop silently; cross-source exact key matches public-apis→APIs.guru ≈ 63 (`openai.com/openai`, `trello.com/trello`, `box.com/box`, …); host-level overlaps 136 hosts guru∩public-apis, 7 uk∩public-apis, 8 gouv∩public-apis, 5 guru∩uk, 1 guru∩gouv. Expect `also_listed_in` on roughly 100–200 records, not thousands.

### Anti-Patterns to Avoid
- **Keying the raw file by `id`** — cross-source duplicates share computed ids; the reader's `Map` would drop records before the merge ever sees them.
- **Reusing `github-fetch.js`** for non-GitHub hosts (PAT leakage, token requirement, body caching).
- **Storing spec bodies** in the sidecar or raw records (D-02; 370 MB).
- **Publishing `--mode=catalog-only` output** — ids differ from full mode for spec-bearing records (`api:stripe.com/stripe` vs `api:api.stripe.com/stripe`), which would churn Vectorize ids and break PRESERVED_FIELDS carry-over.
- **Fetching `machine_documentation_url` specs from data.gouv.fr** or `x-origin` GitHub repos — tempting (1,173 and 1,346 candidates) but outside D-01/D-02 and the budget; list as 4.x levers.
- **Changing `filter.js`, `score.js`, `api.rules.js` thresholds** to make the numbers look better — D-06/D-08: report, do not retune.

| Provenance-stamped access writes | ad-hoc `access.auth.type = …` + manual provenance objects | `setAccessField(access, 'auth.type', v, { method, source_url, confidence })` | validates paths, clamps confidence, stamps `checked_at`; `accessClarity` reads exactly these keys |
| v2 envelope defaults, nullable `repo_*`, id default | per-source record builders that fill every field | emit the raw contract (Pattern 1) and let `upcastRecord` fill the rest | one choke point; 4.1 round-trip test guards it |
| NDJSON I/O | `fs.readFileSync(...).split('\n')`, `JSON.stringify(arr)` | `readNdjsonRecords` / `writeNdjsonStreaming` | F1 invariant + lint |
| Tiering / slugs / scoring / slop | per-type reimplementations | `assignPercentileTiers`, `assignSlugs`, `scoreEntity`, `isSlop` | identical to plugin path; tests exist |
| Hostname parsing | regex on URLs | `hostOf` (+ `new URL` for path checks) | never throws; same function the recipe/slug use |
| Embedding text | custom string for api | `buildEmbeddingInput` registry (`embedding-input/api.js`) | content_sha for non-skill types is derived from it (`embed-skills.js:161`) — any divergence re-embeds |
| Header sentinel | literal `{ _header: true, ... }` | `buildHeader('api')` | schema_version pinned centrally |

**Key insight:** every "new" piece of 4.2 that is not a parser is a clone of a path that already runs daily for plugins; deviations create a second way of doing the same thing and a second place for the F1/F2 lints to miss.

## Common Pitfalls

### Pitfall 1: No `Content-Length` — the 5 MB guard must stream
**What goes wrong:** HEAD-based size checks always pass (`content-length: null`, brotli chunked) and `res.json()` on microsoft graph allocates 34 MB per spec and ~370 MB total.
**How to avoid:** `readBodyCapped(res, 5 MB)` via `res.body.getReader()`; cancel on overflow; mark `spec_parsed: false`. Test with a fake `Response` whose body is a 6 MB stream.
**Warning signs:** harvest RSS > 1 GB; `spec_parsed: false` count ≠ 3 ± a few.

### Pitfall 2: data.gouv.fr cannot be conditionally fetched
**What goes wrong:** assuming "warm runs are mostly 304s" for all sources; the sidecar logic treats a missing ETag as a cache miss every day (fine) or, worse, caches a bogus key.
**How to avoid:** only store sidecar entries when the response carried `etag` or `last-modified`; budget 7 × ~6 s ≈ 45 s per run for gouv; keep the 400 ms spacing.

### Pitfall 3: Sidecar read/write trips the F1 lint
`readFileSync(path, 'utf-8')` anywhere under `scripts/` is Banned-A regardless of path; `JSON.stringify(x, null, 2)` is Banned-B. Add a `LINT_ALLOWLIST` entry for `scripts/lib/feeds/http-fetch.js` ("feeds-etag-cache.json — bounded sidecar ≤ ~3k URL entries, ~400 KB") and write without indent through tmp+rename. The same applies to `scripts/filter-apis.js`'s stats write and to `scripts/report-api-calibration.js` if it reads JSON.

### Pitfall 4: Raw-file key collisions
`readNdjsonRecords` returns a `Map`; keying by `r.id` keeps one record per computed id. public-apis `openai.com/openai` and APIs.guru `openai.com` compute the same id → the merge never sees the pair, `also_listed_in` stays empty, `merged_duplicates` under-counts. Key the raw read by `origin.source + ':' + origin.source_id` (unique per source: guru key, gouv slug, UK url/name, public-apis `API`).

### Pitfall 5: `extra` whitelist drops harvester-only fields
`spec_parsed`, `endpoint_summaries`, `cors` vanish at `upcastRecord`. Either add them to the upcaster + types + one fixture record, or do not rely on them downstream. Decide before writing parsers (Open Question 3).

### Pitfall 6: Id instability between catalog-only and full mode
Spec-derived `base_urls[0]` changes the id host (`stripe.com` → `api.stripe.com`). Also `servers[0].url` may be templated (`https://{region}.example.com`) → `hostOf` returns `''` → id falls back to provider; substitute `variables[*].default` before `hostOf`. Treat `--mode=catalog-only` output as smoke-only.

### Pitfall 7: Gate drops masquerade as "harvest bugs"
With ~1,700 short-description drops and (without `base_urls: [Link]`) ~1,900 public-apis drops, `total_apis` can land near 2.9k. The pre-flight floors are on RAW counts (1,000) so they will not fire; the calibration report must print the `dropped` breakdown per source and gate so nobody "fixes" the harvester.

### Pitfall 8: Multi-scheme specs and the auth mapping
Stripe declares `basicAuth` AND `bearerAuth`. Deterministic choice: use the first top-level `security[]` requirement's scheme if present, else scheme-type priority `oauth2 > http bearer > apiKey > http basic > openIdConnect`. For Stripe the top-level order yields `http_basic` while the 4.1 fixture says `bearer`; the fixture is hand-written, not an oracle — document the rule, test it on the stripe fixture, and let the result stand (or prefer bearer over basic when both exist, which matches how Stripe documents itself; pick one, write it down).

### Pitfall 9: Media-type and license normalisation noise
`*/*`, `applicaiton/xml` (typo in a real spec), `application/pdf`, vendor types. Map a whitelist (`application/json`→json, `application/xml|text/xml`→xml, `text/csv`→csv, `text/plain`→text, `application/x-ndjson`→ndjson, `text/html`→html, `application/pdf`→pdf, `application/octet-stream`→binary, `image/*`→image) and drop the rest. `info.license.name` values like `"Apache 2.0"`, `"MIT License"`, `"Creative Commons Attribution 3.0"` need a small SPDX name map (`MIT`, `Apache-2.0`, `BSD-3-Clause`, `CC0-1.0`, `CC-BY-4.0`, `OGL-UK-3.0`, `LO-2.0`/`etalab-2.0` for lov2, `ODbL-1.0`) else `name` only (scores 70 via `scoreLicense`).

### Pitfall 10: `workflow-flags.test.js` will go red by design
Test 2 asserts zero `env.DATA_FEEDS_ENABLED` step guards and test 1 requires the literal `'false'`. Rewrite both in the same task that edits the YAML (assert exactly N gated steps; assert the fallback literal inside the expression).

### Pitfall 11: The measurement cannot ride main's broken cron
`gh run list`: every scheduled run since at least 2026-10-30 failed — 2026-10-30 → 11-03 at "Upload vectors to Vectorize" (`[upload] loaded 0 vector records` because Track 2 logs `[search] HTTP 401, skipping` → empty raw → empty vectors; the GHA caches `skills-raw-ndjson-361`, `etag-cache-361`, `skill-vectors-361` are 197–217 B), 2026-11-04 at Track 1 (`[pulse] FATAL: failure ratio 18.5% > 15%`). Release assets are stale (`skills-latest` 648 MB from 2026-09-27; `plugins-latest` 2026-09-27). A branch dispatch of `daily-scrape.yml` fails at Track 1/2 before any api step. See Open Question 1.

### Pitfall 12: Local environment is thinner than it looks
`node_modules` in this worktree contains only `esbuild` (no Astro, no hnswlib). `npm test`, lints, `filter-apis`, `embed-skills` (dry run) and `enrich` (exact-engine fallback, fine at N≈4k) all run on built-ins; `npm run build` does not. The calibration run is therefore local-safe; do not plan an Astro build in 4.2. `data/skills.ndjson` is absent locally (only `skills.json`), so never import `src/lib/entities.js` in tests (4.1 Pitfall 5).

### Pitfall 13: Node 20 in the daily workflow
`import.meta.dirname` (used by the Node-22 test job) is 20.11+; `setup-node` resolves the latest 20.x so it would work today, but keep `scripts/` on the `fileURLToPath(import.meta.url)` idiom like every sibling script. `AbortSignal.timeout`, `structuredClone`, `fetch`, `ReadableStream` are all fine on Node 20.

export function parseCsv(text) {
  const rows = []; let row = [], field = '', inQ = false;
  for (let i = 0; i < text.length; i++) {
    const c = text[i];
    if (inQ) { if (c === '"') { if (text[i + 1] === '"') { field += '"'; i++; } else inQ = false; } else field += c; }
    else if (c === '"') inQ = true;
    else if (c === ',') { row.push(field); field = ''; }
    else if (c === '\n') { row.push(field); rows.push(row); row = []; field = ''; }
    else if (c !== '\r') field += c;
  }
  if (field.length || row.length) { row.push(field); rows.push(row); }
  return rows;   // rows[0] = header (12 columns); expect 231 data rows with 12 fields each
}

}

### 4. Streamed body cap + conditional GET (the two behaviours verified live)
```js
export async function politeFetch(url, { fetchImpl = fetch, etagCache, timeoutMs = 20000, maxBytes = Infinity, headers = {} } = {}) {
  const prior = etagCache?.get(url);
  const h = { 'User-Agent': AGENT_UA, Accept: 'application/json, text/csv, text/plain;q=0.9, */*;q=0.1', ...headers };
  if (prior?.etag) h['If-None-Match'] = prior.etag;
  else if (prior?.last_modified) h['If-Modified-Since'] = prior.last_modified;
  const res = await fetchImpl(url, { headers: h, signal: AbortSignal.timeout(timeoutMs), redirect: 'follow' });
  if (res.status === 304) return { status: 304, notModified: true, body: null, capped: false };
  const reader = res.body.getReader(); const chunks = []; let n = 0; let capped = false;
  for (;;) { const { done, value } = await reader.read(); if (done) break;
    n += value.byteLength; if (n > maxBytes) { capped = true; await reader.cancel(); break; } chunks.push(value); }
  const etag = res.headers.get('etag'), lm = res.headers.get('last-modified');
  if (res.ok && (etag || lm)) etagCache?.set(url, { etag, last_modified: lm, checked_at: new Date().toISOString(), status: res.status });
  return { status: res.status, notModified: false, capped, body: capped ? null : Buffer.concat(chunks).toString('utf-8') };
}
```
Retry wrapper: on `429 | ≥ 500 | TypeError/AbortError`, up to 3 retries with `[1000, 4000, 16000]` ms (or `Retry-After` × 1000 capped at 120 s).
