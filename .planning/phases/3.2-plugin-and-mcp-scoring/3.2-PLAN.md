Phase 3.2 expands the ClaudeAtlas catalog pipeline to score, filter, and publish two new entity types — `plugin` and `mcp_server` — using the polymorphic envelope infrastructure shipped in Phase 3.1.2 and the v2 writer pattern shipped in Phase 3.1.4. After this phase ships:

1. `data/plugins.ndjson` and `data/mcp-servers.ndjson` exist as v2 EntityRecord files (schema_version=2 sentinel header + per-record `entity_type` + `extra.*` payload).
2. The daily-scrape cron produces fresh plugin + MCP data alongside skill data, all wired through the existing `scorers`, `filter-rules`, and `recipes` registries — true "add files, don't refactor" as promised by 3.1.2.
3. `/api/v1/search?type=plugin` and `?type=mcp_server` start returning real results because upload-vectors now writes `metadata.entity_type` for plugin and MCP records.
4. Feeds (whats-new / trending / notable) carry mixed-type entries with `_claudeatlas.type_chip` so Phase 3.3+ UI can render type badges.
5. The bidirectional skill↔plugin bundle graph is populated as data — `skill.bundled_in_plugins[]` and `plugin.extra.bundled_skills[]` etc. Display rendering is deferred to Phase 3.3.

**Purpose:** Phase 3.1.2 reshaped the data model specifically so this work could land as additive files. Phase 3.1.3 wired feeds with type-chip support in advance. This phase cashes in on both — turning ClaudeAtlas from a skill index into a true multi-entity Claude-ecosystem index.
